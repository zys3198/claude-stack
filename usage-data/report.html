Parallel Spec-to-Verified Delivery Swarm
A lead agent can decompose a ticket into parallel, isolated workstreams for specification discovery, implementation, test design, independent review, and regression investigation. Each agent works in a dedicated git worktree and returns structured findings, while the lead reconciles the results into a minimal patch that must survive adversarial review and tests. This reduces wrong-approach and buggy-code friction while accelerating multi-file features such as Ticket02, OA work, and cross-layer backend/frontend changes.
Getting started: Use Claude Code subagents with git worktrees, plus MCP context tools such as ctx_search, ctx_read, ctx_patch, and ctx_shell for grounded repository exploration. Require pytest or the repository's existing test runner, and optionally Playwright, as merge gates rather than treating implementation completion as delivery.
Paste into Claude Code:

Create a worktree plan with these roles: (1) specification investigator: extract acceptance criteria, dependencies, and non-goals; (2) implementation agent: propose and implement the smallest coherent change; (3) test agent: identify missing unit, integration, and regression coverage and implement tests; (4) adversarial reviewer: inspect the proposed diff for scope creep, security, concurrency, migration, API-contract, and backward-compatibility risks; (5) runtime verifier: determine the exact commands and environment needed for realistic validation.
