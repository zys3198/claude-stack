# 资产原则

常驻：本文件无 `paths`，每个会话开始即进入上下文。判断一条资产该放哪、以什么形态加载、什么时候该删，只看这里。
日期：2026-09-25 | owner：用户

## 原则

### 表达层 —— 怎么写

| # | 原则 | 判据 |
|---|---|---|
| A1 | 协议化 | 协议 > 文字，schema > 散文 |
| A2 | 结构化 | 固定标题、固定字段 |
| A4 | 命名有语义 | 目录载分类、文件载身份、日期／状态词载时间 |

### 组织层 —— 放哪

| # | 原则 | 判据 |
|---|---|---|
| B4 | 引用 > 复制 | 一知识一源，其余指针 |
| B6 | 加载形态归类 | 每类资产落下面「加载形态」四格之一 |

### 治理层 —— 怎么活

| # | 原则 | 判据 |
|---|---|---|
| C1 | 显式契约 | 触发／输入／输出／权限／失败写清 |
| C2 | 最小权限 | 密钥不入库；工具、网络、写文件显式 |
| C3 | 可验证 | 能机械判的写检查器，判不了的写判据并标明 |
| C4 | 生命周期 | owner／updated／过期；废弃归档 |

**A3 符号化、B1 渐进披露、B2 集中索引、B3 单一事实源、B5 只放必要 五条不在此复述**——文档怎么写、怎么分层、怎么剪除，见 `/writing-for-agents`（插件 skill，按名字引用，不写带版本号的缓存路径）。

## 边界

- 「只放必要」只对运行时被 agent 读取的产物生效；`notes/`（证据）、`installing/`（台账）、`backups/`、`authorization/`（授权登记）的存在理由是可审计，不是必要。
- 不入表：跨代理可移植（不主动引入跨平台抽象，同一平台优先用原生机制）；「怎么用 AI」类建议。
- 引导层（本文件、`CLAUDE.md`、skill）**没有覆盖语义**：两份指令冲突时模型任选其一。要硬约束只能落 `settings.json` 或 hook，因此同一件事禁止存在两份会冲突的副本。

## 加载形态

平台只给四格，每类资产落进其一：

| 形态 | 机制 | 何时进上下文 |
|---|---|---|
| 常驻 | `CLAUDE.md`、无 `paths` 的 `rules` | 每个会话开始 |
| 条件 | 有 `paths` 的 `rules` | 读到匹配文件时 |
| 按需 | skill | 调用，或模型判定相关 |
| 全量 | `@path` 导入 | 会话开始，**不是渐进披露** |

渐进披露靠「L0 放指针 + agent 按需 Read」，不靠平台。

## 资产 → 形态 → L0

| 资产 | 加载形态 | L0 由谁提供 |
|---|---|---|
| `~/.claude/rules/principles.md`（本文件） | 常驻 | 文件自身 |
| `~/.claude/CLAUDE.md` | 常驻 | 路由表 |
| `rules/*.md` | 条件（带 `paths`）／常驻（不带） | 文件头 |
| skill | 按需 | `description` 字段（model-invocable 时每轮常驻） |
| `docs/protocols/*.md` | 不进上下文 | `protocols-index.md` 对应行 |
| memory | 召回 | `MEMORY.md` 索引行 |
| `notes/` | 不进上下文 | 目录名 |
| hook | 不进上下文（平台执行） | `settings.json` matcher |

标「不进上下文」的并非没有入口：协议与 memory 靠 L0 指针单拉，`notes/` 靠目录名找，hook 由平台执行、从不进模型上下文。
