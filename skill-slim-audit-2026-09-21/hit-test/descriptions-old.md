### bidirectional-steelman-by-user
对存在方案取舍的决策/选型/“怎么办”类问题运行双向钢人论证：重述真实目标，分别强化支持与 反对方，找出决定结论的关键变量，给出明确判断和下一步。用户提出“该不该”“值不值得”“哪个 好”“怎么办”这类未决取舍，给出一个方案并隐含征询意见，或明确要求方案对比、双向论证、 正反方分析时触发。只有唯一可验证答案的事实问题、方案已定的执行任务、用户要求直接给结论 时不触发。<!-- v1.2.0 -->

### toolchain-pitfalls-by-user
命令行、解释器、脚本和子代理在本机上反复踩到的坑——路径转换、引号提前展开、代码页与输出编码、包装器与可执行文件、工作树与子代理机制。写脚本、跑命令、派子代理前查一次。

### parallel-delegation-by-user
将边界清楚、可独立验收的任务委派给受控 worker（单个或并行），由主代理统一验收、整合和报告；启动前须向用户展示模型、provider、route、effort、并发与隔离配置并取得确认；仅在收益超过成本时使用。

### docker-only-by-user
本机执行任何命令的去处：构建、测试、装依赖、跑脚本、格式化、生成产物、临时试代码、起服务一律放容器里，宿主机只做只读查看、git 操作与 docker 命令；含一次性容器模板、资源上限、代码来源指向、端口与独占资源归属

### install-ledger-by-user
维护 Claude Code / Codex 的安装台账：登记、核对或追溯 skill、插件、MCP、CLI 和桌面工具的来源与安装状态。用户要求整理台账、登记安装、核对当前状态或追溯归属时使用；不执行安装、卸载、删除或提交。

### task-notes-by-user
跨多轮会话的任务把接续笔记按「入口 → 索引 → 单条」三级存放在仓库根 notes/<任务名>/。跨会话任务开工接手、会话压缩（/compact）前后、定期整理维护时使用。

### article-writer-by-user
创作或深度改写单篇中文技术文章、博客、技术方案、知识库、面试题、单篇教程/实用指南、 工具推荐或面经；用户明确点名本 skill 或明确要求写/改这类单篇内容时触发。 系统教程/系列课/从零学习路径不触发本 skill（模型直接处理，无专用 skill）；写代码/改 bug/ 重构走 coding-workflow-by-user 不触发。

### coding-workflow-by-user
执行代码改动、修复 Bug、重构、审查 AI 代码或回退改动时使用；涵盖改前/改中/改后清单、验证闭环、调试、Agent 调度和止血回退。不用于纯问答、文章写作或学习调研。
