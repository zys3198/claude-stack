### dev-clean-by-user

### bidirectional-steelman-by-user
对存在方案取舍的决策/选型/“怎么办”类问题运行双向钢人论证。用户提出“该不该”“值不值得” “哪个好”“怎么办”这类未决取舍，给出一个方案并隐含征询意见，或明确要求方案对比、双向论证、 正反方分析时触发。只有唯一可验证答案的事实问题、方案已定的执行任务、需求方向不清需要采访 澄清、用户要求直接给结论时不触发。<!-- v1.2.0 -->

### toolchain-pitfalls-by-user
本机命令行、脚本和子代理反复踩到的坑。写脚本、跑命令、派子代理前查一次。

### parallel-delegation-by-user
把边界清楚、可独立验收的任务委派给 worker（单个或并行）。用户要求并行处理、派子代理， 或任务可拆成互不依赖的部分时使用；启动前须向用户展示模型、provider、route、effort、 并发数和隔离方式并取得确认。

### docker-only-by-user
本机要执行的命令一律放容器里：构建、测试、装依赖、跑脚本、起服务前查一次；宿主机只做只读查看、git 操作与 docker 命令。含一次性容器模板、资源上限与端口约定。

### install-ledger-by-user
维护 Claude Code / Codex 的安装台账：登记、核对或追溯 skill、插件、MCP、CLI 和桌面工具的来源与安装状态。用户要求整理台账、登记安装、核对当前状态或追溯归属时使用；安装或卸载动作本身不触发。

### task-notes-by-user
跨多轮会话的任务把接续笔记按「入口 → 索引 → 单条」三级存放在仓库根 notes/<任务名>/。跨会话任务开工接手、会话压缩（/compact）前后、定期整理维护时使用。

### article-writer-by-user
创作或深度改写单篇中文技术内容：文章、博客、技术方案、知识库、面试题、教程、工具推荐、 面经。用户明确点名本 skill 或要求写/改这类单篇内容时触发。系统教程、系列课、从零学习路径 不算（模型直接处理）；写代码、改 bug、重构走 coding-workflow-by-user。

### coding-workflow-by-user
执行代码改动、修复 Bug、重构、审查 AI 代码或回退改动时使用；不用于纯问答、文章写作或学习调研。
