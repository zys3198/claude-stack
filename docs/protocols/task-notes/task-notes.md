# 任务笔记三级结构

任务进行中的笔记按三级拆开，每一级只放下一级需要的东西。写不写看压缩损失，不看跨不跨会话——同宿主同目录的长任务同样写，判据见 [`adjacent-mechanisms.md`](adjacent-mechanisms.md)。

存放位置：`<仓库根>/notes/<任务名>/`，任务名用 `YYYY-MM-DD-主题`；单条笔记再按主题落到子目录，一个主题一个目录，索引按同一主题轴分文件。组织规则见 `~/.claude/docs/protocols-index.md` 的「堆积时的组织」。

## 三级

| 级 | 文件 | 放什么 | 读取时机 |
|---|---|---|---|
| 入口 | `STATE.md` | 目的、进度、下一步候选、未决、最新交接、产物指针表 | 每个新会话开头 |
| 索引 | `ITEMS/<主题>-items.md` | 该主题的清单表格 + 一行一条的记录索引，每条带一句 hook | 要查讲到哪里、有哪些条目 |
| 单条 | `<主题>/<短名>.md` | 一条笔记的固定字段，落在该主题的目录里 | 处理到那一条 |

入口不抄清单，索引不抄正文，正文不抄别处已有的内容、只引路径；索引的 hook 照抄单条的结论，是唯一一处重复。

## 主题目录

主题目录名取人找东西会走的轴（主题或板块），随写随建，写的人定。一个条目横跨两个主题时，按「主要答案落在哪」放一处，另一个主题的索引行指过去。

- 开工先读入口的「下一步候选」，再读 `handoff/` 里最新的交接。
- 同一会话内续写只往主题目录里加文件，不改别的会话写过的文件。
- 索引行指向单条时写相对路径，如 `hooks/hook-dead-binding.md`。索引按主题分文件，跨会话共用；行只由产出它的会话新增，别的会话发现错字可以改，不重排别人的行。
- 入口的进度、下一步、未决三块仍是单份，跨会话共写。
- 会话出口落在 `handoff/<日期>-<短名>.md`，一次会话一份，读完即可删。

## 入口文件

五块都写成一行一条的短句，一行指到单条或主题目录，不复述内容；超过一条短句的内容落成单条，这里留指针。

**未决**一行一条、一条一句话，收三类：待裁决的（拿不准的决定）、越界发现的（顺手活、收不回的操作、必须新增的流程/权限/依赖）、实测异常的（与基线对不上的结果、失效的检查，写「证据：」开头）。证据行排最前，多行原始输出落成单条，这里留指针。

未决不阻塞：记下来继续做不受影响的部分，不停下来等裁决。执行者不能自己批卷，裁决权在交付对象侧，行为约束见 [`execution-discipline.md`](../execution-discipline/execution-discipline.md)。

交付时未决随产物提交，空的也写「无」——这一块不适用下面「有字段没内容就删掉那一行」。

**接手书面任务书时**，把「理解的目标／顺序／最大风险」≤10 行写进进度再动工；这段回执让下一个接手的会话一眼看出理解偏没偏。

下一步候选写明该走哪个 skill 或取哪份材料，接手的会话不用重新判断该走哪条路。

入口每个新会话都要读，它的大小就是每个会话的固定开销，超过一屏就该往索引或单条里挪。

## 索引文件

索引按主题分文件（`ITEMS/<主题>-items.md`），不堆成一份。每份里清单表格在前（条目、状态、出处），记录索引在后，一行一条：

```
- [subagent 委派](hooks/subagent-delegation.md) — 委派省父窗口注意力、烧钱，需要权衡的决策不委派
```

hook 就是单条「结论」那一行的逐字照抄，不另写一句；索引与单条只有这一处重复，因此不会各说一套。结论写的是判断，不写「讲了 subagent」这种同义反复——读索引的人靠这句判断要不要点开。

## 单条笔记

```
# <条目标题>
材料：<出处文件与行号；本会话定的写「本会话」>
结论：<一句判断，这条讲定了什么>
取舍：<选了什么、否掉了什么、为什么>
改动：<改动的文件路径；没有改动写「无」>
未决：<这一条悬着的问题、越界发现或没有证据的说法>
其他：<不属于上面几类、下一个会话又要知道的事实>
```

填好的一例：

```
# subagent 委派
材料：`article-3.md` §1.2、`PHASE-BOUNDARIES.md:36`
结论：委派省父窗口注意力、烧钱，需要权衡的决策不委派。
取舍：需要 worker 在细节上做取舍的任务不委派——worker 看不到父窗口，取舍缺前提。
改动：`parallel-delegation/SKILL.md` 的 Route 第 1 条与 description
```

- 一个字段一行，一行只放一件事；字段之外的正文不写。
- 有字段没内容就删掉那一行；「材料」与「结论」必写，「改动」没改动写「无」。
- 一个字段里超过三条要点，说明这条其实是几条，拆开写。
- 机制解释、举例、推导过程留在原文里，引路径。
- 材料里读出来的收获先问去处：要长期留下的写进 skill、memory 或 `docs/`，笔记只记改到哪、留指针；没有别处可放的，一句结论，或落进「其他」一行。
- 日期不写：单条不带时间轴，要按时间找就看 `handoff/` 的文件名。

下一个会话读这一份、加上它引的材料就能接着做，不依赖对话历史。

## 写作要求

- 及时：时点是相位边界，别等压缩触发才写。需求澄清与拆票结束、实现工单切换、进入验收、发现阻塞或准备交接时，都先更新 `STATE.md`、`ITEMS/<主题>-items.md` 和对应单条笔记。发现阻塞记进未决后继续做别的，不停下来等。
- 只记重点：判据是下一个会话接手需要，且别处拿不回来。材料的复述与解释、讨论过程与轮次、改动的具体内容（git 记得）、已被改掉的说法，都不记。
- 无遗漏：判据是这一条不记、下一个会话还拿不拿得回来。被否掉的路子漏了算遗漏。
- 准确：写错比不写危险，拿不准的标「未验证」。

## 维护动作

每讲完一条三步：在主题目录里建单条笔记文件、索引加一行、入口只改进度那一行。

旧内容过期时就地改掉，不在下面追加新值——两份互相矛盾的说法比缺一条更糟。

定期维护：入口超过一屏、或索引长到扫不完时整理一次。入口的明细外移到索引或单条；索引里已过期且不再适用的行删掉；单条过期就地改。判定不改的条目、已成规则的条目（标「已落地」）不删。

## 校验

`—`：产物是各项目仓库里自由形态的笔记，磁盘上没有可判的固定形态。入口与索引的存在性由 `task-notes-reminder.py`（PreCompact／SessionStart）提醒，不阻断；内容字段合规无机械判据。

## 维护条款

这一节管**本文件自己**；笔记的维护见上一节。

**分界。** 会变的（三级结构、主题目录规则、单条字段表、写作要求）整体重写。只增的：本文件没有——依据留在产出它的单条笔记里，正文不留历史。

删除判据与整理触发点各协议通用，见 `~/.claude/docs/protocols-index.md` 的「维护条款」。

## 任务收尾后的处置

任务做完，把笔记目录列给用户，留档还是删除由用户定，用户不说就留档。留档的随分支并入主干，不改写成摘要、不搬去 `docs/`。

- **收在入口那层**：`STATE.md` 与 `ITEMS/` 保留，正文留在原处靠索引抵达。人的负担只压在入口，想追细节的点开一条。
- **已成规则的标「已落地」**：条目产出了 skill 条款或全局规则时，在索引那一行标注。读的人知道不必重做，要追溯时才点开。
- **判定不改的照旧留**：这类条目的全部价值是防止下个会话把同样的候选重提一遍，删掉等于白判。
