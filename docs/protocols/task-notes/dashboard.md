# 任务看板

[`task-notes.md`](task-notes.md) 的视图层：把 `STATE.md` 已经在维护的那几块渲染成一页 HTML，给用户看，后继会话也可直接读。写看板不是另起一套记录。

## 与源的关系

`notes/<任务名>/STATE.md` 是唯一事实源，看板是它的投影。

- **先写源，再投影。** 进度、未决、下一步三块先落进 `STATE.md`，看板数据段照抄；板上有、源上没有的内容不许出现。
- **agent 读源不读板。** 接手的会话读 `STATE.md`；看板是给人看的渲染，agent 也可以读，但它不是第二份权威。
- **不反向同步。** 两边不一致时以 `STATE.md` 为准，改板不改源。

## 触发

接到预计超过 5 步或预计超过 30 分钟的任务时，动手前读一次。

## 规则

1. **开工前建看板。** 派 `dashboard-builder` 在工作目录的 `.dashboard/<YYYY-MM-DD>-<主题>.html` 建看板。它跑在后台，主会话不等它，继续干活。
2. **派发授权。** `dashboard-builder` 属常设授权，免逐次配置确认。派发时在会话里写一行固定配置——模型 `opus`、effort `medium`、后台、只写 `.dashboard/` 与它自己的记忆——但不等待确认。这是 [`delegation.md`](../delegation/delegation.md) 逐次确认门禁的唯一豁免项，只对它有效。
3. **每步更新。** 每完成一步，主会话用 Edit 只改看板数据段内的 JSON，不重派子代理；同一批内容里，进度、未决、下一步三块先写进 `STATE.md`。
4. **待决不停等。** 需要用户拍板的事写进「待你拍板」块和 `STATE.md` 的未决，并在「默认做法」块写明先按哪条走；然后按默认做法继续，不阻塞。
5. **收尾随任务处置。** 看板不单独定去留，照 [`task-notes.md`](task-notes.md) 的「任务收尾后的处置」——把 `.dashboard/` 与笔记目录一起列给用户，用户不说就留档。

## 不触发

只读调查、单步任务、用户说不用看板。

## 校验

`—`。判的是「该起看板时起没起」，属运行时行为；产物 `.dashboard/*.html` 是各项目仓库里的自由形态记录，`~/.claude` 下没有可判的固定形态。

## 维护条款

**分界。** 会变的（触发阈值、五块内容、豁免范围、看板落点、与 `STATE.md` 的同步规则）整体重写。只增的：（历史变更）只追加，写完不改。
删除判据与整理触发点各协议通用，见 `~/.claude/docs/protocols-index.md` 的「维护条款」。
