# 台账协议

管全局资产的登记与核对。本协议**只写记录**：安装、卸载、物理删除、恢复、移动工具与 skill，修改生产配置、权限或认证数据，以及 commit/push，按全局确认线单独走；已明确授权的范围直接执行，不重复询问。

上一级：资产放置归 `asset-guide`，库级留删归 `asset-auditor`。

## 一、台账分工

| 内容 | 台账 |
|---|---|
| 自建 skill、hook、statusline、全局定制 | `installing/custom-setup.md` |
| 裸 skill、外部仓库、skill 套件 | `installing/skill-install.md` |
| 插件 marketplace、CLI、桌面工具 | `installing/tool-install.md` |
| MCP 服务、MCP 二进制与注册命令 | `installing/mcp-install.md` |

一份台账一类对象，分工写在 `installing/README.md`。新对象归哪本，按「谁提供的、谁更新它」判断。

## 二、二分判据

**现状表只放会变的，流水只放不变的。**

| | 现状表 | 流水 |
|---|---|---|
| 回答 | 现在有什么、在哪、怎么恢复 | 某天改成什么、为什么、错了怎么退 |
| 写一次还是多次 | 同一行反复改 | 只追加，写完不改 |
| 什么时候读 | 每次触发 | 追溯、复盘、查重 |
| 体量 | 一屏内，单表 ≤ 20 KB | 不限 |
| 放哪 | `installing/<台账>.md` | `installing/archive/<台账>.md` |

推论：安装日期、命令原文、验证输出、回退步骤都**不变**，进流水；状态、位置、恢复方式**会变**，进现状表。默认只读现状表；流水按名或按日期定位，`installing/archive/` 默认不读。

## 三、现状表

固定 6 列，顺序固定：

| 名称 | 状态 | 位置 | 出处 | 恢复 | 备注 |
|---|---|---|---|---|---|
| 与磁盘或配置里一致 | 见下 | 磁盘路径，或配置键 | 第三方写仓库地址；自建写 `自建`；移植写 `移植自 <源>` | 见下 | 一句话；日期写 `YYYY-MM-DD`；需要背景写 `见流水 <日期>`；没有写 `—` |

- **状态** 只用 `在用` / `停用` / `已归档` / `待核`。`待核` 是位置没能当场核实的落点，下次触发必须消解。
- **恢复** 写 `git`（在 `.gitignore` 白名单内）、`手工拷贝`（不在 git，迁移会丢）、或安装命令原文。出现 `手工拷贝` 就是有人要为迁移负责。
- 同表内一行一个资产，名称不重复。插件与裸 skill 双形态分别记行，不合并。

## 四、流水

条目固定 5 个字段，顺序固定：

```markdown
### <名称或事件>（YYYY-MM-DD）
- **变更**：
- **依据**：
- **回退**：
- **验证**：
- **未做**：
```

存量条目搬家时一字不动，新写的按这个格式。

**一次变更做两件事**：现状表新增一行或改对应行的状态列，加上流水追加一段。只做其中一件就是台账失真——只改现状表无法回溯，只写流水则现状表开始骗人。

## 五、执行流程

安装、恢复或卸载完成后，**同一轮**做完三件事：

1. **登记** — 现状表出现这一条（新行，或状态列已改），流水追加一段、5 个字段齐。
2. **同步** — `settings.json` 的变更先 dry-run 再同步 DB。`settings-sync-auto.py` 只挂 `PostToolUse(Edit|Write)`；`claude plugin install/uninstall/disable/enable` 这类 CLI 改的 `settings.json` **不触发自动同步**，要手动跑 `python ~/.claude/skills/cc-switch-setting-sync/scripts/sync_claude_common.py`，否则下次切 provider 时会被 DB 旧快照整条回滚。
3. **读回** — 状态列的值与运行时实测相符；不符时以实测改表。

## 六、取证与判定

只在归属不清或状态冲突时读本节；日常登记按上面四节填表即可。

### 取证优先级

1. 当前磁盘、运行时配置、插件清单、Git 状态
2. 官方仓库、官方文档、安装器或包管理器记录
3. 当前台账里的安装命令、位置和验证输出
4. 记忆或历史对话

用户对「自建 / 第三方」的明确判断优先于自动推断。归属判断回答的是「谁做的」；文件是否存在、插件是否启用，各自另找证据。至少核对：对应目录、运行时配置、版本或命令可用性、台账的 Git diff。只有跨归属、迁移、恢复或状态冲突才补查其他台账。证据缺失写「待补 / 未核实 / 当前不可用」三个词之一，只填实测到的值。

### 归属分类

每条记录只能有一个主归属：

- **自建** — 本地定制规则、个人偏好、项目流程，或用户明确认领的 skill → `custom-setup.md`
- **第三方 skill** — 外部仓库提供的裸 skill 或 skill 套件 → `skill-install.md`
- **插件 / 工具** — marketplace 插件、CLI、桌面软件 → `tool-install.md`
- **MCP** — MCP 服务、二进制、注册与运行配置 → `mcp-install.md`
- **项目级 / 配套工作区** — 在对应记录里注明项目路径和作用域

「已删除 / 已卸载 / 已归档」写进状态列。同一仓库的套件按**仓库级**记一条，内部保留与裁剪写备注；来源、安装形态或当前状态明显不同的才拆成单件。

同一 skill 出现多个副本时，**同名不等于同源，哈希相同不等于可删**。报告分「当前 exact duplicate」「同源 / 替代候选」「独立第三方」三类；只按「当前插件已有」判定删除，会漏掉插件套件的裸名副本、改名替代项和已卸载插件的历史来源。

新增 skill 先判归属再登记。判据三条：磁盘上是不是 symlink 指向外部（是则第三方铁证）、有没有自己的 CHANGELOG 或版本演进记录、有没有引用本机私有的 router 或其他自建 skill。**存疑先按第三方记**，日后查清再调整。

`~/.claude/.gitignore` 的 skills 白名单只收自建 skill，加一行 `!skills/<name>/`。**漏加等于没有备份**——`skills/*` 是默认忽略，不在白名单里的目录不进 git，迁移时静默丢掉。

### 最小修改

- 改动限于状态、位置、出处和死引用这几处。
- 历史事实留在流水；现状表里的过期行整行删掉，不留删除线。
- 归属未确认时停在逐项询问。
- 发现已删除 skill 的路由引用，列为待修清单。
- 报告里区分「台账已记」与「安装已生效」两件事，各自附证据。

## 七、删除

- **现状表删行只有一种情形**：对象不再是本机现状。删之前先在流水落一笔，写清删的是谁、依据是什么；已卸载和已删除的整行删掉，只在流水留痕。
- **死引用当场处理**：位置列指向的文件已不在，就删引用或改指向，不留到下次。
- **流水只增不删**。体量超限走下一节的拆分，不是删条目。

## 八、组织规则

- 现状表接近 20 KB 时，先把同类行合并或移出，再添新行。

## 九、自检场景

1. 「整理 skill 安装台账」→ 读现状表核对，不执行删除或安装。
2. 「刚装了一个插件，登记一下」→ 6 列记全，缺失写 `—` 或「待补」。
3. 「安装某 CLI」→ 不误触发台账治理，除非同时要求登记。
4. 「这个 skill 是自建的」→ 记用户归属，同时另核当前路径与 Git 追踪状态。
5. 「这个工具已卸载」→ 现状表整行删掉，流水留一行。

## 十、输出格式

```text
结论：当前台账状态与关键问题
证据：来源 / 当前状态 / 验证方式
已修改：文件与最小差异
未完成：待补证据、待用户确认或未执行动作
验证：Git 状态、目标 diff 检查、实际状态核对
下一步：一个最小可执行动作
```

## 校验

```bash
python ~/.claude/hooks/scripts/ledger_check.py
```

只读。检查列数与顺序、状态枚举、表内名称唯一、单表体量、`archive/` 完整性，以及插件状态与 `settings.json → enabledPlugins` 相符。不挂 hook，不阻断操作。

## 维护条款

**分界。** 落点表、列定义、状态与恢复枚举、执行流程会变，整体重写；流水与历史只追加。

删除判据与整理触发点各协议通用，见 `~/.claude/docs/protocols-index.md` 的「维护条款」。
