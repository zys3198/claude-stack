# 执行纪律协议

管 agent 执行有验收标准的任务时的行为约束：防作弊、三道止损、非阻塞。触发场景是任务**已有验收标准**——有验收命令、有基线数字，或两者之一。不适用无验收标准的探索、调研与讨论。

反向验证（故意制造失败证明检查会响）不在本协议：它的判据来自单次任务书的判卷标准，由写书方逐条指定。

## 防作弊

达标优先于工作量。以下姿势**全算失败**：

| 姿势 | 写法 |
|---|---|
| 跳过测试 | `skip` / `todo` / `xit` / `xfail` |
| 放宽判断 | 降断言、缩容差、改等号 |
| 伪造被测对象 | mock / stub / 假实现替换真实路径 |
| 删测试 | 删除或改名既有测试 |
| 改判卷标准 | 阈值、验收脚本、CI 配置 |
| 吞失败 | `\|\| true` / `catch` 后返回默认值 / 忽略退出码 |

不变量（可对照基线机械判）：

- 测试数 ≥ 基线
- 覆盖率 ≥ 基线
- skipped = 0
- 补测试类任务：实现目录 `git diff` 为空（业务代码一行没动）

## 三道止损

| 触发 | 动作 |
|---|---|
| 同一条验收连败 3 次 | 停手，复盘已证伪假设，换下一项 |
| 结果比开工基线差 | 回滚，如实报告 |
| 已跑满 N 轮 | 满轮即停，如实汇报卡在哪、还差什么 |

回滚一律用文件编辑工具手动恢复，不用 Git 回滚。

**「没做成但说清了」合格，「做了但更糟」不合格。** 结果不如基线时的交付义务是如实报告，不是硬撑。

## 非阻塞执行

遇到需要裁决的点：

```
记进未决 → 继续做不受影响的部分 → 不停下来等
```

三条纪律：

- 顺手活、越界发现、必须新增的流程/权限/依赖 → 记进未决，不顺手做
- 收不回的操作（删数据、改权限）→ 记进未决，跳过，做别的
- 与基线对不上的实测结果 → 记进未决，带证据前缀

执行者不能自己批卷。裁决权在交付对象侧。

## 校验

`—`，判不了：这五条的输入是「基线数字」与「执行者的实测输出」，两者都由执行者在运行时产生，磁盘上没有可判的固定形态。同批产物的形态检查（体积、重复、命名、生命周期）在 `python ~/.claude/hooks/scripts/protocol_check.py`。

「连败 3 次」是五条里唯一有确定形态的（同一命令连续非零退出次数），但计数需要跨调用状态，尚未落 hook。
