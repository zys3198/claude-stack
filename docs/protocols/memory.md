# 记忆协议

跨会话长期事实存 `~/.claude/projects/<项目目录名>/memory/`。按项目分家：目录名是工作目录路径的转写（`C:\ZYS\Workspace` → `C--ZYS-Workspace`），换项目就换一份，不混放。

## 落点

| 内容 | 文件 |
|---|---|
| 索引 | `memory/MEMORY.md`，一个目录只有这一份 |
| 一条记忆 | `memory/<kebab-slug>.md`，一个文件一件事 |
| 删除前的备份 | `memory/recovery/<YYYY-MM-DD>-<原文件名>.md` |

## 固定字段

每条记忆的 frontmatter：

```markdown
---
name: <kebab-case，与文件名一致>
description: <一行摘要，召回时用它判相关性>
metadata:
  type: user | feedback | project | reference
---
```

`metadata` 下的 `node_type`、`originSessionId`、`modified` 由宿主自动写入，不手填、不手改。

正文写事实本身。`feedback` 与 `project` 两类另加两行 `**Why:**` 与 `**How to apply:**`，把判断依据留下——只写结论的记忆，后来接手的人会按自己的理解反着用。

用 `[[name]]` 指向别的记忆。指向尚不存在的不算错，它标记了以后该写的东西。

## 索引

`MEMORY.md` 一行一条，只放指针不放正文：

```
- [标题](file.md) — 一句 hook
```

## 判据

进记忆的四类：`user` 用户是谁（角色、专长、偏好）；`feedback` 用户对我工作方式的指示（纠正与确认过的做法都算）；`project` 进行中的目标与约束，代码和 git 历史里看不出来的；`reference` 外部资源指针。

不进记忆的：仓库里已经记着的（代码结构、过去的修复、git 历史、`CLAUDE.md`）；只对当次对话重要的；未验证的想法（先进临时区，验证后再升正式记忆）；易变的当日状态。

相对日期一律换算成绝对日期——「上周」在两周后就没有意义。

## 删除与覆盖

**删或覆盖任何记忆文件前，先把完整内容写进 `recovery/<日期>-<原文件名>.md`，再删。** 备份不是可选步骤：记忆没有别的副本，`~/.claude` 仓库也不追踪它。

删除判据两条：内容已被环境里的东西覆盖（代码、配置、`CLAUDE.md`）→ 删，它在别处已经权威，留着就是会过期的缓存；指向的文件、函数或开关已不存在 → 删，或改成当前的指向。

项目目录本身被删后，`projects/` 下那份记忆不再被加载、也不会再被召回，成为孤儿。按上面的判据处置——多数该删，它指向的目标整体不存在了；删前先进 `recovery/`。哪些是孤儿由源路径是否还在判定，`hooks/scripts/protocol_check.py` 会把它们单独分组报出来。

引用某条记忆里的文件、函数、配置或行为前，先核对它当前还在——记忆是写的时候为真，不是现在为真。

## 校验

`—`，暂无可机械校验的脚本。可做而没做的是只读核对：索引行数与 `*.md` 条数相符；每条 frontmatter 的 `name` 与文件名一致；`type` 落在四个枚举内。

## 维护条款

**分界。** 落点表、字段表、判据、删除规则会变，整体重写。只增的：本文件没有——依据留在宿主提示、实际目录结构与被引的记忆里，正文不留历史。

删除判据与整理触发点各协议通用，见 `~/.claude/docs/protocols-index.md` 的「维护条款」。

- 2026-09-24 成立。此前约定散在两处：宿主自带的记忆格式说明，以及各项目 `MEMORY.md` 头部各自写的「记忆操作约定」。本文件合并两者，并把宿主负责的字段（`node_type`、`originSessionId`、`modified`）显式标注为由宿主写入，不再算本项目的约定。
