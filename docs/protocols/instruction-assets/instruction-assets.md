# 指令资产协议

管三类由模型或人写给人看的指令资产：**Skill**（`skills/*/SKILL.md`）、**子代理**（`agents/*.md`）与**项目指令文件**（`CLAUDE.md`、`AGENTS.md`、模块说明）。分界、判据与清单在本文件；概念与写法不在本机复述。

上一级：放置与生命周期归 `asset-guide`，库级留删归 `asset-auditor`，文档怎么写、怎么分层、怎么剪除读 `/writing-for-agents`。本协议只管**判据与清单**。

## 一、三类资产的分界

- **放哪**：Skill 提供通用方法、约束和执行接口；`CLAUDE.md` / `AGENTS.md` 提供项目事实、路线、状态和完成证据。宿主迁移先查官方能力、原生包和真实源码，第三方优先插件化。
- **子代理**（`agents/*.md`）：与 Skill 同为按需加载，但装的不是一份方法说明，而是「一个自带工具面、模型档位和写权边界的执行者」。比 Skill 多三件可判的东西——`description` 每轮常驻，供模型决定派不派；frontmatter 写死实际模型档位与工具面；frontmatter 里的 `hooks` 是按 agent 收窄写权的唯一手段。判它的分量比判 Skill 重：字段名不认识就被平台**静默忽略**，不报错，只能靠实测发现。
- **放多深**：每轮都要生效的机械约束放 hook、CI 或 linter；特定流程、模型难猜的判断和可复用检查表放 Skill；被动读取宿主材料只需一行指针。改变宿主材料才构成额外职责。
- **谁来证明**：Runtime 才证明实际加载和行为。文件存在、配置声明或「已执行」都不是生效证据。
- **Skill 之间**：用 `/skill` 形式调用，不跨目录链文件；编排 Skill 可调用执行 Skill，编排之间不互调；核心规则保持模型、供应商和宿主无关，适配放 adapter。

## 二、Skill 审计

### 通用十查

逐项输出 `PASS / FAIL / 不确定`、位置、证据和影响：

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 身份与来源 | name、description、目录和安装来源可追溯 |
| 2 | description 契约 | 同时说明 what/when，不写完整步骤 |
| 3 | 触发边界 | 有具体正向信号和负向边界，不靠「任何/等等」扩张 |
| 4 | 单一职责 | 目标、消费者、产物单一，不把路由/执行/参考/留删混成总管 |
| 5 | 宿主解耦 | 不硬编码项目路径、状态或领域事实 |
| 6 | 模型解耦 | 不绑定模型、供应商或推理档位 |
| 7 | 输入输出 | 必需输入、缺口处理、固定输出和未完成状态明确 |
| 8 | 决策风险 | 默认路径先行，高风险/外发/删除/权限/提交有确认点 |
| 9 | 验证闭环 | 有最小场景，验证加载、行为和结果而非文件存在 |
| 10 | 维护成本 | 版本、证据来源和维护入口可追溯，未验证不进规则 |

对 agent（`agents/*.md`）两项不适用：**#6 模型解耦**——`model`、`effort` 正是它必须显式写死的字段，绑定档位是它的功能不是缺陷；**#15 `context: fork`**——子代理本身就运行在独立上下文里。其余各项照查，把「Skill」读成「agent」。

### 渐进披露追加检查

11. 入口是最小路由器，引用现有 `references/`、`scripts/`，任务外资料不预读；12. 剔除旧模型遗留的重复提醒、过慎审批和可接受的无价值条目；13. 完成证据、停止点和等待理由可观察；14. 区分常驻描述、按需正文、工具输出和交接成本；15. 大量读取、长探索或批处理若宿主支持 `context: fork`，说明隔离与回流边界。

### 类型追加检查

- **Router**：信号表命中即直达；不命中或多解按决策点提问；每条路径有近端负向边界，目标存在且可直达，默认值先于菜单，组合边对称无循环；Skill 集合或职责变化时同步更新 router，不能留下旧目标或漏掉新目标。
- **Executor**：失败、阻塞和重跑行为明确；外部输入先验证；产物可交接；分别报告 `passed`、`failed`、`blocked`、`not-run`。

### 动态验证

description、触发词、负向边界、路由、输入输出、宿主接线或运行参数变化后，准备 3–5 个场景：正向、明确不触发、兄弟 Skill 撞词、缺输入或多解、用户点名下游。观察第一跳是否正确；错误或目标不存在记 P0。行为验证分静态、运行、使用三层；配置或 hook 另做运行时 dump、真实 payload、重载后真实触发。没有子代理时可人工走查，但记录原始错误和「人工走查替代」。

### 分级与输出

P0＝误路由、幻觉目标、危险动作无门或运行完全失效；P1＝触发、输入输出、解耦或交接明显削弱可靠性；P2＝版本、维护、测试资产等非关键缺口。输出必须包含：模式、对象/类型/路径/宿主、静态结果、动态场景与真实输出、减量改前/改后（如适用）、来源结论、P0/P1/P2、已修改、未完成状态和一个最小下一步。未有运行证据不得宣布生效；审计本身不代替用户删除。

## 四、项目指令资产

### 建立项目 AI 上下文

用户要求让 AI 看懂项目、建立或补充项目 AI 上下文时，读 [`instruction-assets/build-project-context.md`](build-project-context.md)。产物输出到 `docs/ai-context/`，由用户审阅后自行落地。

### 审查指令设计

**范围与停止线**：只读取用户明确纳入的自建 `SKILL.md`、`CLAUDE.md`、`AGENTS.md`；不读取或审查 `references/`、`scripts/`、插件 payload、外部 Skill 或其他文件，来源不明标「不确定」。只出审查报告和 diff，不执行 Edit、Write、移动、删除、提交或推送。

**四步**：

1. **定靶**：列文件路径、归属、目的、允许范围；每个文件标记已审查、未读取、读取失败或不在范围。
2. **九项检查**：逐文件输出 `PASS / FAIL / 不确定`、位置、原文、影响和证据，检查触发边界、重复/冲突、资料读取、等待边界、完成标准、留存依据、常驻划分、逐句剪除和时效核对。
3. **证据分级**：`[源码]`、`[执行记录]`、`[官方原则]`、`[规则推测]`、`[未知]` 分开标；静态文字不能冒充运行行为。
4. **输出最小 diff**：每条 FAIL 写位置、最小摘录、场景、证据类型、影响、diff 和保留约束；全部通过时写「无须修改」。

九项检查的操作标准，以及六条冲突判据（两个负担、信息层级、正面陈述、锚定词、context pointer、归置相邻）见 [`instruction-assets/review-basis.md`](review-basis.md)。判断常驻还是按需时，优先保留安全、权限、业务和验收门禁；只在当前分支会改变判断/执行/验收的资料才读取。

**完成条件**：所有范围内文件都有结论；建议含原文、场景、最小 diff、证据类型和保留约束；不同证据等级不混写；未执行内容标 `unknown`、`not-run` 或「未验证」；末尾给一个最小下一步或明确「无需修改」。

### 不得削弱的约束

不得删除或改成模型自行决定：生产生效、不可恢复删除、对外发送/发布、密钥/迁移/生产脚本、技术栈/数据结构/关键业务分支/权限判定确认；子代理启动前展示实际模型、provider、route、effort、并发和隔离并等待确认；代码或业务任务的真实运行、验收、失败修复、重新验证、独立复核、多来源核验、实验授权、用户确认、数据保留和审计记录。

合并、搬运、精简正文时**禁令句必须保持祈使语气**。把 `# 不要用 Browser(url)` 改写成 `# 整轮复用同一标签页`，看起来信息量没少，实际是把约束降级成背景说明——读禁令会改变行为，读描述只增加上下文，模型按签名自然度选 API。禁令要给出**违规的具体写法**，不能只说正确写法；约束最好定位到源码行，冲突时可复核。

### 共用文件策略

- `AGENTS.md` 是内容源，`CLAUDE.md` 只用 `@AGENTS.md` 导入并补 Claude Code 特有内容；不双写、不用 symlink。
- 根文件只留路径与 1–2 句摘要；真正非有不可的内容限于项目说明、非默认包管理器、非标准构建/类型检查命令。根入口预算 ≤120 行。
- 全局规则、项目事实、术语与领域模型、ADR、任务状态、Skill 流程、hook/CI/测试和 memory 分层归置；可复用结论就近落盘并更新根索引，索引过期主动修正。
- 草稿模板见 [`instruction-assets/templates/`](templates/)。

### 吸收外部方法论文章

用户拿方法论文章（AI 工作流、工程实践等）问「能为我做什么」时，先把每条主张归入三类，再谈落盘：

| 类 | 判据 | 去向 |
|---|---|---|
| AI 能自觉做 | 可写成规则或 Skill 让模型自动执行的动作（如委派探索 subagent、TDD、缺信息停下问） | 才可能进 `CLAUDE.md` 或 Skill 正文 |
| 只能人做 | 与模型能力无关、交不出去的判断和操作（业务取舍拍板、划定 out of scope、设计模块接口、视觉与手感 QA、沙箱与权限决策） | 只供人自己学习和保持警觉，**写进规则无效** |
| 人机协作 | 两侧各有固定动作且顺序不可换（grilling、spec、Kanban、代码审阅、QA） | 进工作流设计，用表格列清 AI 做什么、人做什么 |

贯穿性原则（如 feedback loop 质量决定产出上限）单独标注——它决定第一类动作能否成立。

## 五、校验

```
python ~/.claude/hooks/scripts/protocol_check.py --only size,dupe,lifecycle
```

本文件的正文形态由上列三项判据覆盖（体积、重复、生命周期）；运行时传输层是 `hooks/scripts/protocol-report.py`，它不含判据、只按检查器退出码行动。清单语义（skill 该不该留、该收窄还是该归档）判不了，那部分走 `/asset-auditor`。

## 六、维护条款

**分界。** 本文件的正文（分界、清单、判据、流程）是可变区，可以整体重写；依据与历史只追加。删除判据与触发点通用，见 `docs/protocols-index.md`「维护条款」。

**证据顺序**：

1. 当前会话可用 skill/tool/agent 清单。
2. 本机目标文件、宿主文件、安装台账和插件 payload。
3. 官方文档、官方包元数据和真实源码。
4. 实际运行输出、失败复现、动态基线和用户确认。
5. 证据不足时标「不确定」，不拍脑袋补规则。

Memory 只提供历史背景，不证明当前 Skill 可用；迁移路径不证明自建归属。

**证据分层**：每条结论标 `静态`（文件、frontmatter、引用、目录、配置）、`运行`（加载、调用、输入输出、真实触发结果）、`使用`（实际任务是否解决问题；没有数据写「不可用」）、`确认`（用户对技术选型、权限、删除、外发或范围的明确决定）。

**变更门禁**：

- 增删检查项、触发词、路由条目或严重性标准，必须引用真实事故、官方变更或失败测试。
- 只做机械版本戳或维护记录补齐，可不跑动态基线，但必须记录跳过理由。
- description、正向触发词、负向边界、输入输出契约或宿主接线变化，必须跑动态场景。
- 新 Skill 先做不用 Skill 的反向测试；已有能力稳定覆盖时，不新建。
- 库级留删与冷热分级交给 `asset-auditor`，本协议不执行删除。
- 路由目标必须经过当前可用性和来源核验；同名不等于同源，哈希相同也不等于可直接删除。
