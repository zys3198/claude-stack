# 审查基准：垫在检查表之下的六条判据

九项检查可直接执行；本文件是它们背后的判据，用来在两项互相冲突或拿不准时定夺。

**六条判据的正文不在这里**：两个负担、信息层级、正面陈述、锚定词、context pointer、归置相邻的完整定义与判据在通用写作判据 `/writing-for-agents` 里（§The two loads、§Information hierarchy、§When to split、§Steps and completion criteria、§Context pointers、§Leading words、§Pruning）。按 skill 名字引用，不复述正文；本文件只留审查时的操作化改写，以及一条它正文里没有的规则。

## 审查时的操作化改写

- **两个负担**：指针后面的材料靠指针那一行逃脱 context load，没有指针的材料完全压在 cognitive load（人身上的索引成本）上。遇到位置判断时问一句：这次要付哪种成本。十次里只有一次用得上的规则，另外九次都在付 context load。
- **信息层级**：分支是最好的披露判据：每条分支都要的留在文件里，只有部分分支会走到的推到指针后面。拆一次就多付一份负担，所以只在切法值这个成本时才拆，两种切法各自成立：**按分支拆**，让每条路径只带上自己要的材料；**按顺序拆**，一串步骤里靠后的那些会诱使模型赶当前这一步，把它们挡在视野外能逼出更多实际工作——反过来，把两段顺序并进一个文件，会让每一步都看见后面还有什么，诱发过早完成。文档带步骤时，本该披露的文件内参考会盖住步骤，让「要不要照步骤做」变成掷硬币，这既是可读性问题，也让不同次运行走出不同结果。
- **正面陈述**：审查时看到一条禁令，先问能不能改成正面陈述：不能改的只有无法正面表达的硬约束，即便如此也配上正面目标，让注意力落在该做什么上。
- **锚定词**：审查时找展开的表达：同一个意思在三处各写一句、一个指针花一整句去比划一个概念，都是该收成一个词的信号。词的分量也要核：打不过模型默认行为的弱词跟没写一样（模型本来就比较仔细时写「要仔细」），修法是换一个更重的词，重到能把默认行为撬动为止，换别的写法没有用。
- **context pointer**：触发可靠性由指针的**措辞**决定，不由目标决定：该用的材料挂在措辞太弱的指针后面是稳定性缺陷，先把措辞改准，改不动才考虑把材料搬回正文。每条分支配一个触发词，指同一件事的同义词算一条分支写了两遍；指针里不重复正文已经交代过的身份。**指针写多显由依赖强度决定**：没有它输出就是**错的**（硬依赖），写一句显式指针；没有它输出只是**不够锐利**（软依赖），一句模糊的散文提及就够——把软依赖写成硬依赖的措辞属于过度承重，既白占每轮的常驻开销，也把不承重的指针撒得到处都是。
- **归置相邻**：判据是「读起来像一份给 agent 写的说明」——成组的材料像，散落的材料不像。它与重复是两件事：重复把一个意思写在两处，散落把一个意思拆到多处。

## 九项检查操作参考

| 检查项 | 操作标准 |
|---|---|
| 触发边界 | 列具体正向信号和近端负向边界；不把领域相关、单个关键词或“任何/其他/等等”当成无条件触发。 |
| 重复与冲突 | 为每条规则保留一个权威位置；不同文件的优先级、例外和动作一致。发现两个都成立的冲突并列交用户，不自行取舍。 |
| 资料读取 | 只有会改变当前判断、执行或验收的材料才读；任务外材料按需路由。 |
| 等待边界 | 每个等待点写风险、权限或用户决策理由；安全且明确的动作可继续。 |
| 完成标准 | 写可观察证据、停止点和失败/阻塞状态；文件存在、配置声明或“已执行”不是生效证据。 |
| 留存依据 | 规则能说明保留理由；源码一眼可见、通用最佳实践、一次性修复和冗长解释列为候选。 |
| 常驻划分 | 只有每轮必须生效、或应由 hook/CI/审阅者固定执行的内容常驻；特定任务资料按需加载。语言风格、证据门槛和交付自检不得移走。 |
| 逐句剪除 | 对保留内容做 no-op 检查；识别 duplication、sediment、sprawl、relevance，整句删除无行为影响的内容。 |
| 时效核对 | 核对文件、命令、版本和目录仍存在且可用；会随环境变化的具体事实移出常驻文件或改为权威指针。 |

## 证据与输出补充

审查结论分 `[源码]`、`[执行记录]`、`[官方原则]`、`[规则推测]`、`[未知]`；静态文字不能证明运行行为。每条 FAIL 的最小报告应包含位置、原文、场景、证据类型、影响、unified diff 和保留的安全/权限/业务/验收约束；全部通过时写「无须修改」。
