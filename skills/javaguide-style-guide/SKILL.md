# JavaGuide docs/ai 风格判定源

## 0. 定位（先读这节）

本 skill **只判定，不写作**。

| 层 | skill | 职责 |
|----|-------|------|
| 写作执行 | `article-writer` §6 | 怎么写：结构模板、钩子模式、语气、格式、§6.7 写作自检清单、§6.9 反例 11 条 |
| **风格判定** | **本 skill** | 判定达标与否：MUST/SHOULD 二值 checklist + **量化阈值**（article-writer §6 没有） |
| 终检放行 | `publish-final-check` ③ | 调本 skill §1 做风格子项判定 |

**权威关系（重要）**：
- **写作时**以 `article-writer` §6 为基线（含 §6.7 自检"至少一处具体数字"等较松标准）。
- **终检时**本 skill §2 量化阈值**覆盖** §6 对应项——终检比写作基线严（如 M5 写作要求"≥1 处具体数字"，终检要求"≥3 处"）。这是有意的：写时可宽松，发前要硬。
- 本 skill §1 非量化项（M1/M2/M3/M7）与 §6 同义，§3 正反例补强判定。
- §4 反模式与 article-writer §6.9 **互补不重叠**：§6.9 是**写作向**反模式（写时避开），§4 是**判定向**反模式（验收时排除）。

**证据**：本 checklist 反推自 5 篇真实 docs/ai 文章（2026-06-12 抽样，见 §6）。

## 1. 风格 checklist（判定用）

### MUST（不达标 → publish-final-check ③ FAIL）

- [ ] **M1 开头钩子**：个人经历/踩坑/常见误区/行业观察切入（article-writer §6.1 四模式）。**禁定义式开头**。量化：开头前 3 段必含至少 1 个具体场景/数据/痛点，无"XX 是指"。
- [ ] **M2 导航列表**：开头钩子后、正文前，编号列表 5-7 条 + 字数提示（"接近 N 字"），>5000 字加"建议收藏"。（对齐 §6.1，补字数/收藏要求）
- [ ] **M3 H2 问句式**：概念定义/关系对比用疑问句；子模块陈述句。**禁数字前缀**（`## 1 背景`）。（对齐 §6.6）
- [ ] **M4 原创重讲**：理解后重新创作，非近义词替换。自检：随机段对照参考资料，**找不到逐句对应但观点一致 = 过**；逐句对齐只换词 = 不过。（对齐 §6.0）
- [ ] **M5 量化工程感（终检加严）**：概念后跟具体数据/版本/阈值，不泛泛。**终检阈值：全文 ≥3 处具体数字**（写作基线 §6.7 是 ≥1 处，终检覆盖加严）。
- [ ] **M6 时效标注**：引用具体日期（"截至 2025-06-18"），**禁"当前/最新"指代版本**。（对齐 §6.5）
- [ ] **M7 代码块语言标签**：无裸 ``` 块；AI 系列常用 text/json/yaml/mermaid/python/bash。（对齐 §6.4）
- [ ] **M8 格式转换密度**：每 3-5 段纯文字后切格式（代码/表格/列表/blockquote/mermaid）。量化：连续纯文字段 ≤5 段必断。（对齐 §6.7）
- [ ] **M9 收尾自然**：不单独"## 总结"八股段（article-writer §6.1 明确"不需要单独总结章节"）；若加总结，给判断不给复述。**禁"综上所述/总而言之"**。
- [ ] **M10 源码注释与放置**：代码块不裸贴大段实现——关键片段带中文行内注释（解释这段在干什么/为什么这么写）；大段完整实现放末尾独立章节（如 `## 代码实现`），不散落正文。（对齐 §6.4 原则2/3；`绝不裸贴`是硬约束，列 MUST）

### SHOULD（达标加分，不拦发布）

- [ ] **S1 口语化适度**：用"我/我们/Guide/你"，口语词（说白了/搞懂/坑/踩坑）放特定功能位不均匀撒。**注意**：自称以 article-writer §6.2 为准（我/我们/Guide）；"小 G/G 友"仅当原文风需延续时用，不强制。
- [ ] **S2 自曝踩坑/评价**：至少 1 处个人观点/踩坑/反常识（"我觉得""这里有个坑""别指望"）。
- [ ] **S3 Mermaid 配色统一**：用 mermaid 时配色 client 青色/gateway 紫色/business 橙色/infra 紫色/storage 蓝色。（对齐 §6.4）
- [ ] **S4 交叉引用织入正文**：不单独"相关阅读"区块，自然引出同站文章。（对齐 §6.4）
- [ ] **S5 技术术语首现中英对照**。（对齐 §6.7）
- [ ] **S6 段落长短错落**：禁连续 3 段等长。量化见 §2。
- [ ] **S7 表格优先 + 图代源码**：表格作为默认论证载体（对比/参数/场景三件套），复杂逻辑优先 Mermaid 流程图而非堆源码。源码密集型文章表格行数明显多于代码块。（对齐 §6.4 原则1/4；密度偏好因文体而异，列 SHOULD）

## 2. 量化阈值表（终检判定，含可执行 grep 正则）

article-writer §6 没有的判定补强。终检时**覆盖** §6 对应松标准。

| 指标 | 阈值 | 判定法（可执行） |
|------|------|------------------|
| 原创度（M4） | 句子层面逐句对齐率 <20% | 随机抽 3 段，对照参考资料，能逐句对齐的句数占比（人工判定，无 grep） |
| 具体数字密度（M5） | ≥3 处/全文 | `grep -oiE '[0-9]+\s*(ms|s|%|v[0-9]+\.[0-9]+|token|qps|gb|mb|byte|次|倍|个)'` 计数 ≥3 |
| 格式转换间隔（M8） | 连续纯文字段 ≤5 | 按段计数（`\n\n` 分段），纯文字段连续超过 5 即 FAIL |
| 段落等长（S6） | 字符数差 ≥30% 不算等长 | 连续 3 段字符数两两差 <30% → 等长（脚本：`awk` 按空行分段统计每段 `length`） |
| AI 味词（M9） | 0 处 | `grep -nE '综上所述|总而言之|值得注意的是|首先.*其次.*最后|由此可见'` 计数 = 0 |
| 时效词（M6） | 0 处"当前/最新"指代版本 | `grep -nE '当前版本|最新版本|当前的' ` + 人工确认是否指代版本 |
| 口语词分布（S1） | 非均匀（节拍器式 FAIL） | 口语词（说白了/搞懂/坑）出现位置间距标准差 > 均值 50% |
| 代码块语言标签（M7） | 0 个裸块 | `grep -nE '^```$'`（紧跟 ``` 无语言）计数 = 0 |
| H2 数字前缀（M3） | 0 处 | `grep -nE '^##\s+[0-9]+'` 计数 = 0 |
| 大段裸贴代码（M10） | 正文无 >40 行未注释代码块（独立"代码实现"章节除外） | 逐代码块统计行数+查注释；>40 行且无中文注释且不在末尾专节 → FAIL（人工判定，无 grep） |
| 表格 vs 代码比（S7） | 源码密集型文：表格行 ≥ 3×代码块数 | 表格行数（`|` 开头行计数）÷ 代码块数；仅含 ≥5 代码块的源码密集型文适用，概念型文不套 |

无量化阈值的项（M1/M2）按 §3 正反例判定。

## 3. 正反例对照（无量化阈值项 + 量化项典型）

| 项 | ❌ 不合格 | ✅ 合格 |
|----|----------|---------|
| M1 开头 | "RAG（Retrieval-Augmented Generation）是一种结合检索的生成技术。" | "很多团队第一反应是把文档全塞给大模型，问题很快就出来了——这就是没用 RAG。" |
| M2 导航 | 直接进正文无导航 | 开头后加："全文接近 7000 字，主要看这几块：1...2..." |
| M3 H2 | `## 1 RAG 原理` | `## RAG 是怎么工作的？` |
| M4 原创 | 原文"RAG 像开卷考试"→"RAG 如同开卷考" | "RAG 的本质是把检索当外挂记忆，模型答题前先翻资料" |
| M5 数字密度 | 全文仅 1 处"性能提升"（无数字） | "Qdrant 1.x、HNSW ef=128、Recall@10≥0.95，P99 数十毫秒"（4 处数字） |
| M6 时效 | "当前版本支持" / "最新的 SDK" | "截至 2025-06-18，v2.3 支持" |
| M7 代码 | 裸 ` ``` ` 无标签 | ` ```yaml ` / ` ```text ` |
| M8 格式 | 连续 6 段纯文字无切 | 第 4 段后插表格/代码/mermaid 断开 |
| M9 收尾 | "综上所述，RAG 是一项重要的技术。" | "几个判断值得带走：RAG 短期省 fine-tune 的钱，但别指望它消幻觉。" |
| M10 源码 | 正文贴 80 行未注释的完整类实现 | 关键 5-10 行带 `// 解释` 注释；完整实现移到末尾 `## 代码实现` 章节 |
| S7 表格优先 | 6 个代码块讲参数差异，无表格 | 对比表列参数差异，代码只贴 2 个关键片段 |

## 4. 反模式（判定向，与 article-writer §6.9 写作向互补）

article-writer §6.9 已列 11 条**写作向**反模式（写时避开：学术论文腔/翻译体/数字前缀等）。本节补**判定向**（验收时排除），两者互补不重叠：

- ❌ 用本 skill 判定**非 docs/ai 系列**文章 → 本 checklist 仅适用 docs/ai 系列；其他系列（如 Java 核心/面试）走 article-writer 默认模式 + 对应文体规范。
- ❌ 证据失效还在套 → docs/ai 系列文章改版后，抽样证据可能过时；判定前看 §6 抽样日期，超 3 个月标"阈值可能漂移"。
- ❌ 拿本 skill 当写作教程 → 本 skill 只判定；写作走 article-writer §6。
- ❌ MUST/SHOULD 混淆拦截 → publish-final-check 只拦 MUST；SHOULD 仅警告，别升级。
- ❌ 写作基线与终检阈值混用 → 写时按 §6（松），终检按 §2（严）；别用终检阈值卡写作中过程。

## 5. 使用方式

- **终检**（主用）：`publish-final-check` ③ 读 §1 MUST 逐条 + §2 量化阈值（grep 正则），MUST FAIL → 报告列项。SHOULD（S1-S7）对应 publish-final-check §2③ SHOULD 行（S6 跨文件命名对齐；S7 表格/源码比为本 skill 新增）。
- **用户问"够不够 JavaGuide 味"**：取 §1 + §2 判定，给达标率。
- **不写作**：写作请求 redirect `article-writer` JavaGuide 模式。
