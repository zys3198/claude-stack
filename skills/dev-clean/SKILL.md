按顺序执行，每步都把结果给用户看。

**第一步** 运行状态脚本：

```
C:/Users/zys31/AppData/Local/Programs/Python/Python312/python.exe "C:/Users/zys31/.claude/hooks/scripts/session-status.py" $ARGUMENTS
```

**第二步** 先看输出里有没有「活跃会话 枚举失败」。有的话**立即停止**，把这条提示原样报给用户。枚举不可用时「在用」分组必然为空，正在被别的会话使用的工作树会落进「可清理」，照着删会删掉别人正在用的工作树。等枚举恢复后重跑。

确认没有降级提示后，把 `[可清理]` 和 `[游离]` 两组整理成清单。

`[可清理]` 指位于仓库 `.claude/worktrees/` 下的空工作树，用 `git worktree remove` 删除。

`[游离]` 指建在别处的目录，删除前先确认用途。

`[可清理]` 里带「另有 N 项被忽略内容」的项要单独提醒：那是被 `.gitignore` 覆盖的文件，git 不管它们，删除工作目录会一并删掉，且没有其他副本。整理清单时把这些项和它们的文件数一并写出来，让用户先确认再同意。

**孤儿目录只报告，不删除。** 它们在磁盘上有完整工作副本，但 git 已经不再注册，里面的改动不在任何分支上。清单里标了有没有同名分支：标「无同名分支，内容只在此目录」的那些，目录是内容的唯一副本，删掉就找不回来了。这类目录由用户自己判断怎么处理。

**第三步** 项目任务结束前，先完成版本收尾：

1. 只查看并暂存当前任务的文件，不把其他会话或用户改动带入提交。
2. 提交前运行并记录：
   - `git status --short`
   - `git diff --stat`
   - `git diff --cached --stat`
   - `git diff --check`
3. 提交到当前功能分支；提交信息准确描述本次任务。禁止在此步骤使用 Git 回滚覆盖用户改动。
4. push 前列出完整命令、远程仓库、目标分支和影响范围；未获对应远程仓库与分支范围授权时取得确认，已授权不重复询问，再执行 `git push <remote> <branch>`。禁止 push `main`、`master` 或 `develop`，禁止 force push；不执行 fetch/pull 代替验证。
5. push 后再次检查 `git status --short`、`git diff --check` 和最新提交，确认工作区只剩明确登记的内容。

push 未获授权时，可以完成本地提交，但必须明确标记“未 push”，不能把本地提交报告为远程已同步。

**第四步** 列出准备删除的完整路径清单；未获删除范围授权时等用户明确同意，已获授权直接执行。删除不可恢复，临时脚本、截图、日志和容器挂载产物也要逐项列出；任务笔记、证据和用户指定保留的产物不得顺手删除。

**第五步** 用户同意后逐项执行：

```
git -C <仓库路径> worktree remove <工作树路径>
```

只删工作目录，不删分支。分支会留在 `git branch` 里，随时可以重新检出。

有未提交改动的工作树会被 `git worktree remove` 拒绝，这是设计如此。被拒绝时把改动归位到分支上再删。

容器、网络、卷、镜像、构建缓存和服务按准确名称盘点；不删除数据库卷、共享数据或其他会话资源。常驻服务和容器的停止、删除或 `compose down` 逐项列出影响后执行；未获对应停止或删除范围授权时先询问，已获授权不重复询问。

**第六步** 汇报删了几项、失败几项、失败原因、提交哈希、push 状态和剩余工作树/资源。失败项保留原样。
