# 台账协议：流水与归档

现状表的 6 列定义在 [`../SKILL.md`](../SKILL.md)。

## 二分判据

**现状表只放会变的，流水只放不变的。**

| | 现状表 | 流水 |
|---|---|---|
| 回答 | 现在有什么、在哪、怎么恢复 | 某天改成什么、为什么、错了怎么退 |
| 写一次还是多次 | 同一行反复改 | 只追加，写完不改 |
| 什么时候读 | 每次触发 | 追溯、复盘、查重 |
| 体量 | 一屏内，单表 ≤ 20 KB | 不限 |
| 放哪 | `installing/<台账>.md` | `installing/archive/<台账>.md` |

推论：安装日期、命令原文、验证输出、回退步骤都**不变**，进流水；状态、位置、恢复方式**会变**，进现状表。

## 流水

条目固定 5 个字段，顺序固定：

```markdown
### <名称或事件>（YYYY-MM-DD）
- **变更**：
- **依据**：
- **回退**：
- **验证**：
- **未做**：
```

存量条目搬家时一字不动，新写的按这个格式。

## 一次变更做两件事

1. **现状表**：新增一行，或改对应行的状态列。
2. **流水**：追加一段。

只做其中一件就是台账失真——只改现状表无法回溯，只写流水则现状表开始骗人。

## 删除

- **现状表删行只有一种情形**：对象不再是本机现状。删之前先在流水落一笔，写清删的是谁、依据是什么。判据见 [`../SKILL.md`](../SKILL.md)。
- **死引用当场处理**：位置列指向的文件已不在，就删引用或改指向，不留到下次。
- **流水只增不删**。体量超限走「组织规则」的拆分，不是删条目。

## 组织规则

- 一份台账一类对象，分工写在 `installing/README.md`。新对象归哪本，按「谁提供的、谁更新它」判断。
- 插件与裸 skill 双形态分别记行，不合并。
- `installing/archive/` 默认不读，按名或按日期定位。
- 流水单体超过 200 KB 时按年拆成 `archive/<台账>-<年>.md`，纯 move。
- 现状表接近 20 KB 时，先把同类行合并或移出，再添新行。

## 校验

```bash
python ~/.claude/skills/install-ledger/scripts/ledger_check.py
```

只读。检查列数与顺序、状态枚举、表内名称唯一、单表体量、`archive/` 完整性，以及插件状态与 `settings.json → enabledPlugins` 相符。不挂 hook，不阻断操作。
