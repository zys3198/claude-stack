# 取证与判定

只在归属不清或状态冲突时读本文件。日常登记照 [`../SKILL.md`](../SKILL.md) 填表即可。

## 取证优先级

1. 当前磁盘、运行时配置、插件清单、Git 状态
2. 官方仓库、官方文档、安装器或包管理器记录
3. 当前台账里的安装命令、位置和验证输出
4. 记忆或历史对话

用户对「自建 / 第三方」的明确判断优先于自动推断。归属判断回答的是「谁做的」；文件是否存在、插件是否启用，各自另找证据。

至少核对：对应目录、运行时配置、版本或命令可用性、台账的 Git diff。只有跨归属、迁移、恢复或状态冲突才补查其他台账。

证据缺失写「待补 / 未核实 / 当前不可用」三个词之一，只填实测到的值。

## 归属分类

每条记录只能有一个主归属：

- **自建** — 本地定制规则、个人偏好、项目流程，或用户明确认领的 skill → `custom-setup.md`
- **第三方 skill** — 外部仓库提供的裸 skill 或 skill 套件 → `skill-install.md`
- **插件 / 工具** — marketplace 插件、CLI、桌面软件 → `tool-install.md`
- **MCP** — MCP 服务、二进制、注册与运行配置 → `mcp-install.md`
- **项目级 / 配套工作区** — 在对应记录里注明项目路径和作用域

「已删除 / 已卸载 / 已归档」写进状态列。

同一仓库的套件按**仓库级**记一条，内部保留与裁剪写备注；来源、安装形态或当前状态明显不同的才拆成单件。插件与裸 skill 双形态分别记行。

同一 skill 出现多个副本时，**同名不等于同源，哈希相同不等于可删**。报告分「当前 exact duplicate」「同源 / 替代候选」「独立第三方」三类；只按「当前插件已有」判定删除，会漏掉插件套件的裸名副本、改名替代项和已卸载插件的历史来源。

新增 skill 先判归属再登记。判据三条：磁盘上是不是 symlink 指向外部（是则第三方铁证）、有没有自己的 CHANGELOG 或版本演进记录、有没有引用本机私有的 router 或其他自建 skill。**存疑先按第三方记**，日后查清再调整。

`~/.claude/.gitignore` 的 skills 白名单只收自建 skill，加一行 `!skills/<name>/`。**漏加等于没有备份**——`skills/*` 是默认忽略，不在白名单里的目录不进 git，迁移时静默丢掉。

## 最小修改

- 改动限于状态、位置、出处和死引用这几处。
- 历史事实留在流水；现状表里的过期行整行删掉，不留删除线。
- 归属未确认时停在逐项询问。
- 发现已删除 skill 的路由引用，列为待修清单。
- 报告里区分「台账已记」与「安装已生效」两件事，各自附证据。

## 自检场景

1. 「整理 skill 安装台账」→ 读现状表核对，不执行删除或安装。
2. 「刚装了一个插件，登记一下」→ 6 列记全，缺失写 `—` 或「待补」。
3. 「安装某 CLI」→ 不误触发台账治理，除非同时要求登记。
4. 「这个 skill 是自建的」→ 记用户归属，同时另核当前路径与 Git 追踪状态。
5. 「这个工具已卸载」→ 现状表整行删掉，流水留一行。
