# 安装台账治理

> **自动化（2026-09-04 起）**：`hooks/install-ledger-reminder.py`（PostToolUse Bash）捕获安装/卸载命令，
> 追加 `installing/auto-log.jsonl` 兜底并提醒正式登记。本 skill 的「登记」步骤由该提醒触发或用户点名时执行。

## 触发

用户明确提出以下台账意图时，由助手自行调用本 skill；用户显式调用 `/install-ledger` 仅作备用：

- 整理 / 清理 / 核对安装台账
- 登记刚安装的 skill、插件、MCP、CLI 或桌面工具
- 台账和当前机器状态不一致
- 某个 skill / 插件来源、归属或安装位置需要追溯

只有“安装 X / 卸载 X”而没有台账意图时，不触发本 skill；那是执行安装或卸载任务。

## 边界

本 skill 只维护记录，不执行以下动作：

- 安装、卸载、物理删除、恢复或移动工具/skill
- 修改生产配置、权限或认证数据
- commit、push、force push

这些动作即使用户同时提出，也先把台账工作与实际操作分开；高风险动作按全局确认线处理。

台账分工：

| 内容 | 台账 |
|---|---|
| 自建 skill、hook、statusline、全局定制 | `installing/custom-setup.md` |
| 裸 skill、外部仓库、skill 套件、历史来源 | `installing/skill-install.md` |
| 插件 marketplace、CLI、桌面工具 | `installing/tool-install.md` |
| MCP 服务、MCP 二进制与注册命令 | `installing/mcp-install.md` |

## 执行流程

### 1. 先定范围

先列出：目标台账、要核对的对象、允许修改的文件、是否只整理记录。已有用户改动必须保留，不先做全文件重排。

### 2. 取证

按以下优先级判断事实：

1. 当前磁盘、运行时配置、插件清单和 Git 状态
2. 官方仓库、官方文档、安装器或包管理器记录
3. 当前台账中的安装命令、位置和验证输出
4. 记忆或历史对话

用户对“自建 / 第三方”的明确判断优先于自动推断；但不能把用户归属判断当成当前文件存在或插件启用的证据。

至少核对：

- skill 目录和 `SKILL.md` frontmatter
- 插件 `known_marketplaces.json`、`installed_plugins.json`、`settings.json`
- CLI/桌面工具的实际版本或命令可用性
- MCP 注册配置与服务状态
- 目标台账的 Git diff，避免覆盖先前改动

证据缺失时写“待补 / 未核实 / 当前不可用”，不猜来源、日期、版本、命令或使用次数。

### 3. 分类

每条记录只能有一个主归属：

- **自建**：本地定制规则、个人偏好、项目流程或用户明确认领的 skill；写入 `custom-setup.md`。
- **第三方 skill**：外部仓库提供的裸 skill 或 skill 套件；写入 `skill-install.md`。
- **插件 / 工具**：marketplace 插件、CLI、桌面软件；写入 `tool-install.md`。
- **MCP**：MCP 服务、二进制、注册和运行配置；写入 `mcp-install.md`。
- **项目级 / 配套工作区**：不冒充全局 skill；在对应记录中注明项目路径和作用域。

“已删除 / 已卸载 / 已归档”是状态，不是新归属。保留在原归属台账，明确标注当前状态、处置日期、清理范围和恢复方式。

### 4. 维护条目

新增或修正条目尽量包含：

- 来源与精确 URL；未知写待补
- 安装 / 更新 / 卸载日期
- 原始安装命令；未知写未留存
- 实际安装位置
- 依赖与权限面
- 当前状态：启用、禁用、存在但未启用、已卸载、已删除、已归档
- 验证证据
- 可逆恢复路径

同一仓库的套件按仓库级记录；只有来源、安装形态或当前状态明显不同，才拆成单件。插件与裸 skill 双形态必须分别记录，不能用“已安装”混写。

自建 skill 还必须在 `~/.claude/.gitignore` 的 skills 白名单加入对应目录；第三方和插件不加入白名单。

### 5. 最小修改

- 优先改状态、来源、位置和死引用，不整体重写历史。
- 历史事实保留，但过期内容加状态标签，不能让读者误以为仍可用。
- 用户未确认归属时停在逐项询问，不擅自移动记录。
- 发现已删除 skill 的路由引用，列为待修清单；不在本 skill 中顺手扩大修复范围。
- 不把“台账写了”报告成“安装已生效”；运行状态必须单独核验。

## 触发可靠性

自然语言命中台账意图时由助手自行调用，不在 `CLAUDE.md` 增加路由条目；显式 `/install-ledger` 只作触发失败时的备用入口。描述只覆盖台账治理信号，不抢普通安装、代码修改或 skill 设计任务。

## 最小验收场景

执行本 skill 后，至少能得到以下结果：

1. 用户说“整理 skill 安装台账”→ 读取并核对对应台账，不执行删除或安装。
2. 用户说“刚装了一个插件，登记一下”→ 记录来源、命令、位置和启用状态；缺失字段标待补。
3. 用户说“安装某 CLI”→ 不误触发台账治理，除非同时要求登记。
4. 用户说“这个 skill 是自建的”→ 记录用户归属，同时另核当前路径和 Git 追踪状态。
5. 用户说“这个工具已卸载”→ 保留历史条目，改为已卸载状态，不把它写入当前可用清单。

## 输出格式

```text
结论：当前台账状态与关键问题
证据：来源 / 当前状态 / 验证方式
已修改：文件与最小差异
未完成：待补证据、待用户确认或未执行动作
验证：Git 状态、目标 diff 检查、实际状态核对
下一步：一个最小可执行动作
```
