# 双向钢人论证

用于决策和分析，不用于已经确定方案后的纯执行。目标不是制造平衡，而是降低 AI 顺着用户预设结论走的风险。

## 触发范围

使用本 skill 的场景：

- 用户要求判断、建议、选型、比较、取舍或决策
- 用户问“该不该”“值不值得”“哪个好”“怎么办”
- 用户给出一个方案并隐含询问是否应采用
- 技术、产品、流程或个人计划存在未决权衡

跳过本 skill 的场景：

- 纯改代码、查资料、写文章、执行命令或其他已决定方案的任务
- 用户明确说“直接给”“别折腾”，按用户要求直接回答
- 事实问题只有唯一可验证答案；先查证，不把查证问题伪装成权衡

## 方法

按以下顺序完成一次简版论证：

1. **重述真实问题**：区分用户表面提问和实际要解决的目标；指出当前决策对象和边界。
2. **强化双方论证**：分别给出支持方案与反对方案的最强版本。反方不能用稻草人论证，优先补足其合理动机、收益、成本和失败条件；不默认用户预设正确。
3. **找关键变量**：列出真正改变结论的约束、证据、风险、成本、时间、可逆性和未知项。只保留影响判断的变量。
4. **给判断和下一步**：明确推荐、拒绝或条件性结论；说明决定性理由、剩余风险和最小下一步。缺证据时标明不确定性，不编造确定性。

确认性事实仍需查证，证据优先于论证；钢人论证不能替代源码、官方文档或实际验证。

## 输出格式

控制在 1–2 屏，按需使用以下结构：

```markdown
结论：<明确判断>

真正要解决的问题：<目标与边界>

支持方案的最强理由：<钢人化支持论证>
反对方案的最强理由：<钢人化反对论证>

关键变量：<会改变结论的 1–3 个因素>
下一步：<最小可执行动作>
```

问题很简单时可压缩为结论、关键理由和下一步；不要为了形式强行展开四段。只输出摘要化、可审计的理由，不展开内部隐藏推理过程。

## 行为边界

- 先给结论，再给足以审计结论的关键依据。
- 明确区分事实、假设、价值偏好和未知项。
- 不为制造“双方都有道理”而回避判断。
- 不把用户要求执行的任务重新变成方案讨论。
- 用户收回分析要求时立即停止本 skill，按新要求处理。
