# 任务笔记三级结构

跨会话任务的笔记按三级拆开，每一级只放下一级需要的东西。

存放位置：`<仓库根>/notes/<任务名>/`，任务名用 `YYYY-MM-DD-主题`；单条笔记再按会话落到子目录，一个会话一个目录，会话之间不混放。

## 三级

| 级 | 文件 | 放什么 | 读取时机 |
|---|---|---|---|
| 入口 | `STATE.md` | 目的、当前会话目录名、进度、下一步候选、未决、产物指针表 | 每个新会话开头 |
| 索引 | `ITEMS.md` | 清单表格 + 一行一条的记录索引，每条带一句 hook | 要查讲到哪里、有哪些条目 |
| 单条 | `<会话目录>/<编号>-<短名>.md` | 一条笔记的固定字段，落在产出它的那个会话的目录里 | 处理到那一条 |

入口不抄清单，索引不抄正文，正文不抄别处已有的内容、只引路径；索引的 hook 照抄单条的结论，是唯一一处重复。

## 会话目录

会话目录名用 `<日期>-s<序号>`，如 `2026-09-21-s2`；序号从 1 起，按该任务已有的会话目录递增。

- 开工先读入口的「当前会话」行。那个目录是自己这个会话写过的（上下文里还有当时的内容）就沿用它；认不出就是新会话，取下一个序号新建目录，并把入口那一行改成新目录。
- 同一会话内续写只往自己的目录里加文件，不新建目录，也不改别的会话目录里的文件。
- 索引行指向单条时写相对路径，如 `2026-09-21-s2/18-single-run-first.md`。总索引是一份，跨会话共用；行只由产出它的会话新增，别的会话发现错字可以改，不重排别人的行。
- 入口的进度、下一步、未决三块仍是单份，跨会话共写。

## 入口文件

五块都写成一行一条的短句，一行指到单条或会话目录，不复述内容；超过一条短句的内容落成单条，这里留指针。未决一行一条、一条一句话。

下一步候选写明该走哪个 skill 或取哪份材料，接手的会话不用重新判断该走哪条路。

入口每个新会话都要读，它的大小就是每个会话的固定开销，超过一屏就该往索引或单条里挪。

## 索引文件

清单表格在前（编号、条目、出处），记录索引在后，一行一条：

```
- 4 [subagent 委派](2026-09-21-s1/04-subagent-delegation.md) — 委派省父窗口注意力、烧钱，需要权衡的决策不委派
```

hook 就是单条「结论」那一行的逐字照抄，不另写一句；索引与单条只有这一处重复，因此不会各说一套。结论写的是判断，不写「讲了 subagent」这种同义反复——读索引的人靠这句判断要不要点开。

## 单条笔记

```
# <编号> <条目标题>
材料：<出处文件与行号；本会话定的写「本会话」>
结论：<一句判断，这条讲定了什么>
取舍：<选了什么、否掉了什么、为什么>
改动：<改动的文件路径；没有改动写「无」>
未决：<这一条悬着的问题，或没有证据的说法>
其他：<不属于上面几类、下一个会话又要知道的事实>
```

填好的一例：

```
# 4 subagent 委派
材料：`article-3.md` §1.2、`PHASE-BOUNDARIES.md:36`
结论：委派省父窗口注意力、烧钱，需要权衡的决策不委派。
取舍：需要 worker 在细节上做取舍的任务不委派——worker 看不到父窗口，取舍缺前提。
改动：`parallel-delegation/SKILL.md` 的 Route 第 1 条与 description
```

- 一个字段一行，一行只放一件事；字段之外的正文不写。
- 有字段没内容就删掉那一行；「材料」与「结论」必写，「改动」没改动写「无」。
- 一个字段里超过三条要点，说明这条其实是几条，拆开写。
- 机制解释、举例、推导过程留在原文里，引路径。
- 材料里读出来的收获先问去处：要长期留下的写进 skill、memory 或 `docs/`，笔记只记改到哪、留指针；没有别处可放的，一句结论，或落进「其他」一行。
- 日期不写，会话目录名里有。

下一个会话读这一份、加上它引的材料就能接着做，不依赖对话历史。

## 写作要求

- 及时：时点是相位边界，别等压缩触发才写。需求澄清与拆票结束、实现工单切换、进入验收、发现阻塞或准备交接时，都先更新 `STATE.md`、`ITEMS.md` 和对应单条笔记。
- 只记重点：判据是下一个会话接手需要，且别处拿不回来。材料的复述与解释、讨论过程与轮次、改动的具体内容（git 记得）、已被改掉的说法，都不记。
- 无遗漏：判据是这一条不记、下一个会话还拿不拿得回来。被否掉的路子漏了算遗漏。
- 准确：写错比不写危险，拿不准的标「未验证」。

## 维护动作

每讲完一条三步：在本会话目录里建单条笔记文件、索引加一行、入口只改进度那一行。

旧内容过期时就地改掉，不在下面追加新值——两份互相矛盾的说法比缺一条更糟。

定期维护：入口超过一屏、或索引长到扫不完时整理一次。入口的明细外移到索引或单条；索引里已过期且不再适用的行删掉；单条过期就地改。判定不改的条目、已成规则的条目（标「已落地」）不删。

## 维护条款

这一节管**本文件自己**；笔记的维护见上一节。

**分界。** 会变的（三级结构、会话目录规则、单条字段表、写作要求）整体重写。只增的：本文件没有——依据留在产出它的单条笔记里，正文不留历史。

删除判据与整理触发点各协议通用，见 `~/.claude/docs/protocols-index.md` 的「维护条款」。

## 任务收尾后的处置

任务做完，把笔记目录列给用户，留档还是删除由用户定，用户不说就留档。留档的随分支并入主干，不改写成摘要、不搬去 `docs/`。

- **收在入口那层**：`STATE.md` 与 `ITEMS.md` 保留，正文留在原处靠索引抵达。人的负担只压在入口，想追细节的点开一条。
- **已成规则的标「已落地」**：条目产出了 skill 条款或全局规则时，在索引那一行标注。读的人知道不必重做，要追溯时才点开。
- **判定不改的照旧留**：这类条目的全部价值是防止下个会话把同样的候选重提一遍，删掉等于白判。

## 与相邻机制的区别

- **什么时候写**：判据是压缩损失。自动摘要挑不出来的（为什么这么选、被否掉的路子、下一步、未决）在压缩或切换前落盘。可携带性不设门槛：换宿主、换目录或仓库、交给同事、分叉出独立支线照写，同宿主同目录的长任务同样写。
- memory：跨会话长期事实，跟着用户走；任务笔记是任务内的接续材料，任务结束后按「任务收尾后的处置」一节处置。
- **与另外两处不混同**：`docs/` 是给项目参与者读的正式文档，skill 的 `references/` 是给未来的 agent 读的规程；任务笔记是一次性材料，只给下一个会话的 agent 读。
- compact：摘要挑「这段对话讲了什么」，笔记挑「下一个会话接手需要什么」。所以笔记不能等压缩时靠自动摘要代劳——「为什么这么选」和「下一步」只有当事人挑得出来。
- handoff：以 `STATE.md`、`ITEMS.md` 和单条笔记作为接续入口；交接材料必须足以让后续 agent 在没有聊天隐式状态的情况下继续。
