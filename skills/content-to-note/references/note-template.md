# 笔记模板(content-to-note)

三来源共用的整理骨架。提取后按此写成 Markdown,存到本次调用指定的笔记目录

## frontmatter

```yaml
---
date: YYYY-MM-DD            # 发布日期(无则用提取日期)
source: <原文URL>
author: <作者/公众号/UP主>
tags: [主题标签]
status: raw                 # raw=刚提取未精修, reviewed=已校对
---
```

## 骨架

```markdown
# <标题>

> <作者> | <发布日期>

## TLDR
2-3 句:这篇/这条讲了什么、核心结论、值不值得细看。

## 正文
按内容结构化整理(不是流水账搬运):
- 图文/教程类:按章节或知识点分小节,保留关键步骤、参数、判断标准
- 视频类:按学习模块组织(不按分P机械压缩),每模块含核心概念 + 关键步骤 + 常见坑
- 观点类:论点 → 论据 → 适用边界

## 关键收获
3-5 条可复用的结论/方法/判断标准。

## 来源与覆盖
- URL / BV号 / 视频时长 / 字幕或转写覆盖
- 局限(字幕缺失/转写质量/只覆盖部分)
```

## 来源适配

- 公众号:正文从 `#js_content` 提取,保留图片 URL;author = 公众号名。
- B站:标 UP主 + 时长 + 字幕/转写来源;有评论时只写有学习价值的(纠错/补充/争议/替代方案)。
- 抖音:标 作者 + 时长 + 转写来源;短视频按「问题背景 → 判断 → 论据 → 适用边界」组织。

## 不合格的笔记

- 只有「核心观点 + 分P摘要」却无概念拆解、步骤、自测
- 开头大段来源信息,读者看半天不知道学了什么
- 只复述作者立场,不写适用条件、反例、失败场景
- 视频只抓到部分字幕/转写却没标覆盖范围

## B站学习型笔记扩展

B站笔记默认使用以下 13 个部分；短内容可合并，但不能退化成分P流水账：

1. `# 标题`
2. `## 学完你应该获得什么`
3. `## 一句话总论`
4. `## 适用场景与前置知识`
5. `## 知识地图`
6. `## 核心概念卡`
7. `## 方法或流程`
8. `## 关键洞察`
9. `## 实践清单`
10. `## 坑点与反例`
11. `## 自测题`
12. `## 证据与原文位置`
13. `## 来源、覆盖与局限`

写作时先解释为什么和如何迁移使用，再说明作者说了什么；长课程按学习模块组织，每个模块包含目标、概念、步骤、坑和可操作结论；技术内容保留架构、数据流、代码思路、配置、评估和排错；评论只吸收纠错、补充案例、实践经验、替代方案和争议。写前按归档的 `note_budget.json` 定标，写后评分只做验收微调，不用热度替代证据。

正文证据使用统一数字编号，在来源前放 `## 证据脚注`，脚注链接必须能回到包含完整证据 ID 的归档文件。只拿到标题、目录、部分分P或质量不可用的字幕时，明确覆盖范围和局限。
