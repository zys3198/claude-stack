# §1.6 工作树与本地资源

本机同时可能处在三种做法下，隔离要求和收尾责任各不相同，收工纪律完全相同：

| 做法 | 隔离 | 谁收尾 |
| --- | --- | --- |
| 单会话，不派子代理 | 直接用主检出 | 自己 |
| 单会话，派多个子代理 | 每个写任务的子代理各自一个工作树 | 父会话 |
| 同时开多个会话 | 每个任务各自一个工作树 | 各会话自己 |

脚本在本 skill 的 `scripts/` 下：`session-inventory.py` 清点工作树、端口占用、独占容器、stash 和无远端分支。它依赖 psutil，用 `C:/Users/zys31/AppData/Local/Programs/Python/Python312/python.exe` 运行；换机器改这一行。

开工前：

- **一个任务一个工作树**：不共用主检出。会话开始时看到「另有 N 个会话在用当前目录」的卫生提示，先调用 `EnterWorktree` 迁移再动手。
- **一个端口一个实例**：启动前先看占用者（进程名、工作目录、根路径），再决定复用还是显式接管；端口配置必须显式失败，不顺延到下一个端口。
- **独占资源先协商**：占用端口、容器或共享数据库之前，有活跃会话在用就先协商，协商不下交用户裁决。
- **写库先确认**：会写共享数据库的进程（应用、数据库迁移）启动前，先确认目标数据库和迁移开关。
- **本机配置**：端口表和独占操作写在 `~/.claude/session-hygiene.json`。端口与容器属于本机资源，配置跟着机器走，不放进任何仓库；脚本读到就用，读不到跳过上面两节。

收工前：

- **自己的收尾清单**：停掉自己启动的进程，删掉本会话建的空工作树，汇报分支名、路径和未完成项；在做的工作落到自己的分支上并 push。有未提交改动的工作树不删。
- **子代理留下的工作树由父会话收尾**：子代理结束时，宿主在自动清理前会检查未提交改动与未推送提交，两者任一存在就把工作树留在原地。父会话要核对它留下了什么，有价值就提交并推送，确认没价值再手动删除。不处理的话，那份改动只存在于那个工作树里，永远收不了尾。

删错了怎么找回：删除工作树只删目录和 `.git/worktrees/<名字>/` 记录，分支与提交都不动；`git add` 过的内容已进对象库，可用 `git fsck --unreachable` 捞回，没 `git add` 的改动只存在于文件里。未提交的改动还可从会话记录 `~/.claude/projects/*/*.jsonl` 还原，窗口由 `cleanupPeriodDays` 决定。

**功能分支归并**（模块制项目）：模块主开发分支名称以项目约定为准（例如 `oa-finance`、`eam-ems`）。开始任何新工作之前，先把该模块尚未并入的既有分支全部并入模块主开发分支。之后固定走五步：一、以已经并入全部改动的模块主开发分支为基准创建功能分支；二、在该分支上开发和测试；三、测试通过后合并回模块主开发分支，在模块主开发分支上再测试一次；四、用模块主开发分支提交 MR；五、完成善后（停掉自己启动的进程、清理工作树、汇报分支名与未完成项）。不同模块的主开发分支同级，不互相合并。
