# Instruction Auditor — 指令资产审查

把一组指令文件当作一个系统审查，减少误触发、上下文浪费和过早停止，同时保留安全、权限、业务和验收门禁。

## 范围

只读取用户明确纳入的：

- 自建 Skill 的 `SKILL.md`
- `CLAUDE.md`
- `AGENTS.md`

不读取或审查 `references/`、`scripts/`、插件 payload、外部 Skill 或其他文件。来源不明确的文件标为“不确定”，不按目录位置猜测归属。

本 Skill 只出审查报告和 diff，不执行 `Edit`、`Write`、移动、删除、提交或推送。

## 审查基准

- description 尽可能短，只说明 what 和 when；根文档是最小路由器。
- 详细资料按任务需要读取，不把无关文档设成每次必读。
- 工作流不要写成限制模型判断的固定长食谱；保留真正不可猜的约束。
- 开始任务前定义可观察的完成条件；探索任务同时定义探索范围和停止点。
- 安全且目标明确的动作不因流程习惯停住；确有风险、权限或用户决策时才等待。

## 审查流程

### 1. 定靶

列出文件路径、文件归属、审查目的和允许范围。保留已有改动，不扩大文件范围。每个目标文件都要有以下结论之一：已审查、未读取、读取失败或不在范围。

### 2. 五项检查

对每个目标文件逐项输出 `PASS / FAIL / 不确定`、位置、原文、影响和证据。

| 检查项 | 通过标准 |
|---|---|
| 触发边界 | 有具体正向信号和负向边界；不把相关领域、单个关键词或“任何/其他/等等”当成无条件触发 |
| 重复与冲突 | 同一规则只有一个权威位置；不同文件的优先级、例外和动作一致；不重复要求模型本来会做的常规检查 |
| 资料读取 | 只在资料会改变当前判断、执行或验收时读取；按需路由，不强制预读任务外材料 |
| 等待边界 | 每个等待点有风险、权限或用户决策理由；安全明确的动作可继续；必要 checkpoint 不被删除 |
| 完成标准 | 开始前写明可观察完成证据、停止点和失败/阻塞状态；不把文件存在、配置声明或“已执行”当作生效证据 |

### 3. 证据分级

每项判断标注一种或多种证据：

- `[源码]`：目标 Markdown 当前文字直接证明。
- `[执行记录]`：真实运行日志、产物或测试输出证明；没有记录就不能声称发生过事故或已生效。
- `[官方原则]`：文章或官方文档提出的通用原则。
- `[规则推测]`：根据静态规则推断的风险，必须写明尚未观察到实际影响。
- `[未知]`：缺少决定结论所需的文件或运行证据。

静态文字不等于运行行为。没有执行记录时，把结论写成“规则推测”或“未验证”。

### 4. 输出发现

每条 `FAIL` 或有必要的最小改进都必须包含：

```text
文件位置：<path:line>
当前原文：<最小完整摘录>
适用场景：<什么输入或任务会触发问题>
证据类型：<源码 / 执行记录 / 官方原则 / 规则推测 / 未知>
影响：<误触发、上下文浪费、重复执行、过早停止或验收失真>
最小修改 diff：
<unified diff>
保留约束：<安全、权限、业务、验收或用户确认线>
```

只报告能改变行为的改动；全部通过时报告“无须修改”，不凑 diff。

## 不得削弱的约束

不得把效率建议变成以下门禁的删除理由：

- 推生产、删除不可恢复数据、对外发送或发布；密钥修改、数据库迁移、生产脚本执行并入对应门禁。
- 技术栈变更、数据结构调整、关键业务分支、权限或角色判定修改前的确认和依据检查。
- 子代理启动前展示实际可见的模型、provider、route、effort、并发数和隔离方式，并等待用户确认。
- 代码或业务任务的真实运行、验收、失败修复、重新验证和独立复核。
- 业务要求的多来源核验、实验授权、用户确认、数据保留和审计记录。

可以收窄触发、改成按需读取或合并重复文字，但不能把必要权限、风险判断或业务验收改成“模型自行决定”。

## 完成条件

审查完成必须同时满足：

1. 所有纳入范围的文件都有结论；未读取项明确标记原因。
2. 每条建议都有原文、场景、最小 diff、证据类型和保留约束。
3. `[执行记录]`、`[官方原则]` 和 `[规则推测]` 没有混写。
4. 未执行文件修改；未验证内容标为 `unknown`、`not-run` 或“未验证”。
5. 报告末尾给出一个最小下一步，或明确“无需修改”。
