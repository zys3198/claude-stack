## 最弱处（用于 darwin Phase 2 优化方向）

1. **子系列专属反例缺位**（影响三个 prompt 的"反例防护"维度，统一扣 2 分）。§6.9 的 11 条反例全部是通用层（学术论文腔/翻译体/数字前缀等），缺少针对 practices/cases/概念系列的专属反例。建议补：
   - practices 反例：命令清单无场景说明、风险分层变简单三档无判断标准
   - cases 反例：场景变操作日志无 AI 介入点、AI 效果截图与正文脱节
   - 概念系列反例：锚定比喻只出现一次就消失、导航列表字数与实际偏差过大

2. **可执行性的"主题→结构映射"引导缺失**（影响三个 prompt 的"可执行性"维度，统一扣 1 分）。skill 给了结构骨架和实例，但未教 LLM 如何把**新主题**映射到结构上。建议补一节"主题→结构映射法"：
   - 命令类主题 → 命令清单按"拦截/审计/恢复"或"生产/ staging/开发"分类
   - 诊断类主题 → 验收维度按"RT/QPS/内存/错误率"选
   - 抽象概念 → 锚定比喻降级方案（找不到生活场景时改用对比表/类比已有技术）

## 与不带 skill 的 baseline 对比

**质量提升明显的点：**
- **签名分化**：裸 LLM 写 JavaGuide 文章会混用自称（"我/Guide/笔者"随机）、混用结尾（cases 加参考资料或不加随机）、混用截图位。skill §6.3 行 358-371 八维度差异表是核心增量，让 LLM 可控区分。
- **误区破题开头**：裸 LLM 倾向"今天我们来学习 X"或学术摘要开头，skill §6.1 行 248 + §6.2 行 276-286 强制误区破题范式，是 JavaGuide AI 系列最鲜明的签名。
- **锚定比喻机制**：裸 LLM 用随机比喻（用一次就丢），skill §6.2 行 292-300 明确"会被后文反复回引的锚定比喻"——这是概念系列质量分水岭。
- **导航列表仪式**：裸 LLM 不会主动加"接近 7000 字+建议收藏+5-7 条要点"，skill §6.1 行 250-256 强制。
- **实战系列三件套**：裸 LLM 写 practices 容易只给命令清单而漏模板/踩坑，skill §6.3 行 346-349 明确"必须"三件套。
- **勘误提醒防过拟合**（行 309）：skill 主动纠正了旧版词表的臆造词汇，这是 baseline 不具备的自我修正能力。

**skill 引入的潜在负面影响：**
- **过度结构化风险**：skill 的结构骨架非常具体（如 practices 八段式、cases 七段式），LLM 可能机械填空而牺牲内容自然度。对短文（<3000 字）或非典型主题，强行套结构反而显得模板化。
- **自称分化可能过度敏感**：skill 强调 cases vs practices 自称差异，LLM 可能在用户实际想要混合风格时僵硬切换。但这是设计意图（保签名纯度），属可接受代价。
- **导航列表的字数估算**：skill 要求"接近 7000 字"这类字数提示，但 LLM 在创作前无法准确估算最终字数，可能给出误导性字数。这是 skill 没有明确处理的执行盲区。
