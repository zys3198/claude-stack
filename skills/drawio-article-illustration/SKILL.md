# 技术文章配图：决策 → 生成 → 验证

## 核心理念

配图不是为了让文章看起来热闹。一张图至少要解决一个问题：

- **让流程更清楚** — 读者不用在脑子里跑多步逻辑
- **让对比更直观** — 不用同时记多个名词来回比
- **降低认知负荷** — 不用靠文字在脑中构建拓扑结构

判断标准：删掉图，读者还能不能轻松理解这段内容？能 → 不需要图。不能 → 需要图。

---

## 工作流程

```
文章内容 → [Step 1: 扫描决策] → 配图清单 → [Step 2: 逐图生成] → [Step 3: 图文校验] → 完成
```

### Step 1: 扫描决策 — 找出配图点

通读文章，逐段判断是否满足配图条件。输出一张决策表：

| 段落/章节 | 内容类型 | 建议配图 | 图表类型 | 理由 |
|-----------|---------|---------|---------|------|
| 2.1 请求链路 | 流程型 | ✅ 要配 | 流程图 | 5步调用，纯文字读者跟丢 |
| 2.3 三种策略对比 | 对比型 | ✅ 要配 | 对比表/矩阵 | 3x4 维度对比，脑记不住 |
| 3.1 模块职责 | 描述型 | ❌ 不配 | — | 标题重排一遍，没新增信息 |
| 2.2 类继承关系 | 结构型 | ✅ 要配 | 类图/架构图 | 层级深，文字难以说清 |

**配图条件（满足任一即可）：**

1. **流程型**：正文有 3+ 个串行/并行步骤，或含分支/回退/循环。→ 流程图、时序图
2. **结构型**：正文描述 3+ 个组件的拓扑关系（分层/依赖/继承/通信）。→ 架构图、组件图
3. **对比型**：正文有 2+ 个方案/概念的 ≥3 个维度的对比。→ 对比表、决策矩阵、雷达图
4. **状态型**：正文描述了实体在多种状态间的转换条件。→ 状态机图
5. **时序型**：正文描述了多方交互的消息顺序（谁先调谁）。→ 时序图

**不配图条件（有任一即跳过）：**

- 图只是把正文小标题重新排了一遍，没有新增理解视角
- 内容用 1-2 句话就能说清，图没有任何简化
- 图片信息稀疏（节点≤2 且连线≤1），纯装饰
- 同等信息用表格 2 行就能呈现

### 🔴 STOP — Step 1 完成检查

决策表产出后：
- ✅ 至少识别出 1 个配图点 → 继续 Step 2
- ❌ 文章无配图点 → 告知用户"本文无需配图"，终止流程

### Step 2: 逐图生成 — 委托 drawio-chart

每张待配图，按以下顺序操作：

1. **明确图表契约**（用 3-5 句话定死）：
   - 这张图要回答什么问题？
   - 图里必须出现哪些节点/实体？
   - 图里绝对不能出现哪些东西？
   - 节点之间的关系类型（调用/包含/转换/对比）？
   - 有没有分支/回溯/异常流？

2. **委托 drawio-chart 生成（单文件多页模式，默认）**：
   - 默认把所有配图装进 **一个** `.drawio` 文件，每个 `<diagram>` 一张图。
   - 委托时声明"单文件多页模式"，drawio-chart 按此生成多 `<diagram>` 结构（见 drawio-chart §二「多页文件结构」）。
   - 逐张把上文拟定的图表契约传给 drawio-chart，由它填入对应 `<diagram>` 页。
   - 需要时查阅 `drawio-chart` skill 获取配色、布局、字体规范。
   - 用户明确要求"每图一个文件"时 → 降级为多文件模式。

3. **命名规范（单文件多页，默认）**：
   - **主文件名** = 文章文件名（去扩展名）。例：`process-and-thread.md` → `process-and-thread.drawio`
   - **子图 `<diagram name="">`** = 英文 kebab-case，对应该配图点语义。例：`thread-lifecycle`、`process-vs-thread`、`context-switch`、`thread-state`
   - **多文件降级模式**：`{文章简称}-{段落}-type.drawio`（type ∈ flow/arch/seq/compare/state）

4. 生成后默认用 draw.io 桌面版打开让用户预览微调（多页模式下打开主文件即可逐页查看）。

**失败处理**：
- drawio-chart skill 不可用 → 降级输出 Mermaid 文本图，告知用户"drawio-chart 不可用，已用 Mermaid 替代"
- 生成 XML 格式错误 → 标记该图"生成失败"，跳过继续下一张
- 文件写入失败 → 尝试写入 `/tmp` 或 `%TEMP%`，告知用户路径

### 🔴 STOP — Step 2 完成检查

所有图生成后：
- ✅ 至少 1 张成功 → 继续 Step 3
- ❌ 全部失败 → 输出失败原因列表，建议用户手动配图

### Step 3: 图文校验 — 找漏

图生成后，逐图做三轮检查：

**第一轮：结构一致性**
- 正文写了 N 个步骤/组件 → 图里画了几个？多/少了？
- 图里出现的每个节点 → 正文是否都有对应解释？
- 箭头方向是否和正文描述的调用/数据流方向一致？
- 分支条件是否和图外的文字说明一致？

**第二轮：命名一致性**
- 同一实体，正文和图中用的名字是否完全一致？
- 缩写/全称混用？（如正文写 "Large Language Model"，图里写 "LLM"）
- 术语是否和文章其他章节统一？

**第三轮：信息密度**
- 这张图是否让读者更快理解？还是只是把文字搬进框里？
- 有没有冗余节点可以合并？
- 有没有关键信息正文写了但图漏了？

> **技巧**：校验时可把 `.drawio` 文件和文章内容一起给另一个模型做交叉比对。模型擅长发现"正文写了 3 步，图里画了 4 步""图里有个节点正文完全没解释"这类机械性不一致。但最终判断仍由你来做——图有没有让文章更容易读。

## 配图决策速查

### 流程图

**该用：** 有步骤顺序、有判断分支、有回退/重试循环
**不该用：** 只有 2 步线性操作（"打开冰箱 → 放进大象"不需要图）

```text
流程图关键检查：
□ 起点和终点明确？
□ 每个菱形判断都有 Yes/No 两个出口？
□ 异常流/失败路径画了吗？
□ 是不是画了正文没描述的步骤？
```

### 架构图

**该用：** 多服务/多模块的拓扑关系，数据流向跨多个层
**不该用：** 单层简单调用（"Controller 调 Service"一句话说清）

```text
架构图关键检查：
□ 每个方框都对应正文有解释？
□ 层级/分组关系正确？
□ 数据流方向（上行/下行）标注清楚？
□ 没有正文没提的组件？
```

### 对比图/表

**该用：** 3+ 维度，2+ 方案，读者需做选择
**不该用：** 两方案只有 1 个维度不同，一句话就能说清

```text
对比图关键检查：
□ 维度是读者关心的，不是凑数？
□ 每个格子内容正文有依据？
□ 结论/推荐有数据支撑？
□ 维度排列逻辑（重要性/类别）合理？
```

### 时序图

**该用：** 多方交互，消息顺序重要，有同步/异步区分
**不该用：** 单次 request-response，不需要显式画时序

```text
时序图关键检查：
□ 所有参与方都列出来了？
□ 消息顺序和时间轴一致？
□ 同步/异步用实线/虚线区分？
□ 没有正文未描述的消息交互？
```

## 反模式：这些情况不要配图

1. **标题搬家**：图 = 正文 h2/h3 的框框版，零新增信息
2. **信息稀疏**：2 个节点 1 条线，图形复杂度 < 文字理解成本
3. **脱离正文**：图里出现正文完全没提的概念/缩写/组件
4. **装饰性配图**："这篇文写得好，加张图点缀一下"
5. **重复信息**：同一信息正文有表格，图再画一遍表格 → 留表格删图
6. **过度配图**：一篇文章塞 10+ 张图，读者看图的时间比看文字还长

## 与 drawio-chart skill 的协作

本 skill 负责"判断→规划→校验"，`drawio-chart` skill 负责"画图"。

```
drawio-article-illustration (本 skill)    drawio-chart skill
─────────────────────────────────────    ──────────────────
扫描文章、找配图点                       ↓
确定图表类型、拟定节点清单               ↓
画图委托 ─────────────────────────────→  生成 .drawio XML
                                        导出 PNG/SVG/PDF
图文一致性校验 ←────────────────────────── 返回文件
输出校验报告
```

画图前把图表契约写清楚再委托，减少返工。

---

## 校验报告模板

每张图校验完成后输出如下格式：

```markdown
### 校验报告：{图表文件名}

| 检查项 | 结果 | 说明 |
|-------|------|------|
| 组件数量一致 | ✅ / ❌ | 正文 N 个，图 N 个 |
| 每个节点有解释 | ✅ / ❌ | {如有遗漏列出缺失节点} |
| 方向/流程正确 | ✅ / ❌ | {如有错误说明} |
| 命名一致 | ✅ / ❌ | {如有不一致列出} |
| 无冗余信息 | ✅ / ❌ | {如有可合并节点列出} |

**综合判断**：{✅ 通过 / ⚠️ 需微调 / ❌ 需重画}
**修改建议**：{具体修改点}
```

## 失败模式处理

| 场景 | 触发条件 | 处理 |
|------|---------|------|
| drawio-chart 不可用 | skill 未安装或调用失败 | 降级输出 Mermaid 文本图，标注"需手动转为 drawio" |
| 文章为空或太短 | 正文 < 200 字 | 告知用户"内容过短，暂无配图点"，终止 |
| 校验不通过 | 综合判断 ❌ 需重画 | 回到 Step 2 重新生成该图，最多重试 1 次 |
| 用户拒绝某张图 | 用户说"这张不要" | 从配图清单移除，不重试 |
| 文章已有配图需 review | 用户提供已有图+文章 | 跳过 Step 1-2，直接进入 Step 3 校验 |
