# Skill 根入口减量方法

用户要求缩小单个 Skill、减少调用后的上下文，或在保持效果的前提下精简 `SKILL.md` 时读取本文件。目标是降低实际加载成本并保护信息层级，同时保持触发、执行、安全门禁和验收行为。

## 先分清测量对象

分别记录四项，不用磁盘总体积代替上下文成本：

1. **固定注入**：`CLAUDE.md`、`AGENTS.md` 等每轮常驻内容。
2. **路由描述**：model-invoked Skill 的 name 与 description 常驻成本；`disable-model-invocation: true` 的 Skill 按宿主真实行为核验。
3. **调用正文**：Skill 触发后进入会话的 `SKILL.md` 内容；正文会在后续轮次继续占用上下文。
4. **按需材料与回流**：本次分支实际读取的 references、脚本输出、工具结果和交接材料。

`scripts/`、未读取的 references、测试和模板只占磁盘时，不列为本次上下文减量目标。除非用户明确要求缩小安装包，否则不要为了字节数删这些资产。

## 信息层级

逐段分类，每段只能有一个主要归属：

| 层级 | 判据 | 动作 |
|---|---|---|
| 根入口步骤 | 每次调用都要按顺序执行 | 留在 `SKILL.md`，写清完成标准 |
| 根入口参考 | 每个分支都可能需要，且查阅成本高 | 留在 `SKILL.md`，与所属概念放在一起 |
| 分支参考 | 只有特定来源、模式或阶段需要 | 原文迁入 `references/`，根入口留下 context pointer |
| 环境事实 | 配置、目录、脚本 `--help` 或源码可直接查到 | 指向权威来源；只保留隐藏约定、原因和已验证坑点 |
| 可删除内容 | 重复、过期、无关，或不改变模型行为的 no-op | 有证据后整句删除 |

**分支测试**：所有合理执行路径都需要的内容留在根入口；只被部分路径读取的内容进入对应参考文件。每一行都成立但整体仍过长，属于 `sprawl`，用分支披露处理。

## Context pointer 合同

每个指针同时写清：

1. **何时读取**：使用可观察的来源、模式、阶段或失败条件，前置触发词。
2. **里面有什么**：列出会改变当前判断、执行或验收的内容。
3. **读取强度**：必需资料写“必须读取”；可选资料写具体条件，不写含糊的“按需参考”。

范式：

```markdown
- 进入某个分支时，必须读取该 Skill 中对应的现有 reference；
  其中包含会改变当前判断、执行或验收的规则与失败回退。
```

目标材料重要但模型没有读取时，先增强指针条件，再考虑移回根入口。新建参考文件只在分支真实互斥、节省的注意力大于导航成本时成立。

## 减量流程

### 1. 固定基线

记录目标路径、归属、调用方式、现有未提交改动、入口行数与字节数、引用文件、已有测试和行为合同。先确定不得削弱的触发、输入输出、安全、权限、业务和验收门禁。

### 2. 绘制分支表

列出每个用户目标或运行模式，以及该分支真正需要的步骤和参考。无法放进任何分支、也非所有分支共同需要的段落，进入删除候选。

### 3. 先做原文迁移

先把分支专用段落原样移动到同一 Skill 的 `references/`，保留标题、规则、例外和完成标准；根入口增加符合上述合同的指针。结构迁移与语义改写分开，避免同时变化后无法定位回归原因。

### 4. 再做逐句剪除

只处理有证据的四类内容：

- **duplication**：同一含义已有权威位置；保留单一事实来源。
- **sediment**：外部行为变化后留下的过期层。
- **relevance**：与 Skill 当前职责、分支或验收无关。
- **no-op**：删除后，相同模型在对照场景中的行为没有变化。

环境一眼可查的信息留给环境。查询昂贵、原因不可见或坑点已反复发生时，可以保留缓存，并注明保留理由。

### 5. 保持完成标准

压缩步骤文字时保留可观察、可穷尽的完成条件。优先删除解释性铺陈，不删除决定做多深、何时停止和失败如何报告的句子。

## 不得作为减量对象

- 生产、删除数据、外发、权限和角色修改的确认门禁。
- 信任边界的输入验证与防止数据损失的错误处理。
- 用户固定偏好、业务规则、模型无法从环境推断的约束。
- `passed`、`failed`、`blocked`、`not-run` 等真实状态区分。
- 目标、guardrail、holdout 和实际运行验证。
- 当前任务之外的用户未提交改动。

这些内容可以移动到正确层级、合并重复表达，不能借减量名义削弱。

## 行为等效门禁

静态改短不能证明效果不变。候选必须与基线使用同一套：

- 模型、宿主、工具和运行参数；
- 正向分支、负向边界、缺失输入和兄弟 Skill 撞词场景；
- `runs`、超时和 grader；
- target、guardrail、holdout。

验收顺序：

1. 每个分支都从根入口读取到正确参考文件。
2. target 全部通过。
3. guardrail 全部通过。
4. holdout 无回归。
5. 实际加载的上下文减少；无法观测时标为 `not-run`，字节估算不能冒充运行值。

模型输出无需逐字一致；比较任务结果、关键判断、门禁、产物和失败状态。确定性脚本或模板可以增加内容 hash、文件清单和退出码对照。

正式候选与基线比较可交给 `/improver-skill`；它拥有相同条件、target、guardrail、holdout 和 apply 门禁。本 Skill 负责找出该移、该删、该留的位置，并产出候选结构。

## 输出合同

减量审计额外输出：

```text
对象：路径、调用方式、现有改动基线
测量：改前/改后行数与字节数；固定注入/描述/正文/回流材料的测量等级
分支表：分支 → 必需步骤与参考
保留：所有分支共同需要的内容
迁移：原位置 → reference 路径 → pointer 条件
删除：原文、分类、行为证据
门禁：不得削弱的安全、权限、业务和验收规则
验证：baseline/candidate/target/guardrail/holdout 的真实结果
未完成：blocked、not-run 或待用户确认
```

缺少运行证据时可以交付静态候选和测试计划，结论写“未验证”，不能宣称效果不变。
