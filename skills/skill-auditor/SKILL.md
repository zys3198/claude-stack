# Skill 审计与设计器

负责**单个** Skill 的 router、executor、reference、maintenance 审计、设计、组合检查和根入口减量；不替用户决定整个 Skill 库留删。每条结论绑定本地事实、官方变更、真实事故、运行输出或失败测试；无证据标「不确定」。

## 核心边界

- Skill 提供通用方法、约束和执行接口；`CLAUDE.md`/`AGENTS.md` 提供项目事实、路线、状态和完成证据；Runtime 才证明实际加载和行为。
- 跨多个 `SKILL.md`、`CLAUDE.md`、`AGENTS.md` 的指令质量审查或项目上下文草稿，转交 `instruction-engineering`；库级留删转交 `asset-auditor`。
- 每轮机械约束放 hook、CI 或 linter；特定流程、模型难猜的判断和可复用检查表才放 Skill。被动读取宿主材料只需一行指针，改变宿主材料才构成额外职责。
- Skill 之间用 `/skill` 形式调用，不跨目录链文件；编排 Skill 可调用执行 Skill，编排之间不互调；核心规则保持模型、供应商和宿主无关，适配放 adapter。

## 通用原则与模式

渐进披露、证据闭环、安全不降级和不加冗余机制是默认原则：入口保留用途/触发/边界/配套资料，分支细节按需读；开始前定义范围、停止点和可观察证据；不删除生产、数据、外发、权限、用户确认、失败修复、重新验证或独立复核门禁。

| 用户目标 | 模式 | 产物 |
|---|---|---|
| 检查既有 Skill | 单 Skill 审计 | 静态结果、运行证据、分级问题 |
| 新建或重写 | Skill 设计 | 触发契约、正文、场景、维护入口 |
| 缩小一个入口 | 减量审计 | 改前/改后测量、迁移清单、等效门禁 |
| 检查多个搭配 | 组合审查 | 边界、交接、归属、循环、兜底 |
| 判断来源/重复 | 来源审计 | exact duplicate、同源替代、独立第三方、不确定 |

用户只要结论就不改文件；明确要求修改才进入设计或修复。

## 第 0 步：定靶与取证

确认目标路径、名称、宿主、用户目标和是否允许修改；读目标 `SKILL.md` 全文及 frontmatter，仅按目标读取配套测试、引用它的 router 和维护文件；记录类型、来源证据、现有改动与目标外文件，不覆盖、删除或提交。候选根入口减量必须读取 [`references/skill-size-optimization.md`](references/skill-size-optimization.md)；审计本 skill 自身，或改其检查项、变更门禁与同步文件清单时，读 [`references/MAINTENANCE.md`](references/MAINTENANCE.md)。

## 第 1 步：通用十查

逐项输出 `PASS / FAIL / 不确定`、位置、证据和影响：

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 身份与来源 | name、description、目录和安装来源可追溯 |
| 2 | description 契约 | 同时说明 what/when，不写完整步骤 |
| 3 | 触发边界 | 有具体正向信号和负向边界，不靠“任何/等等”扩张 |
| 4 | 单一职责 | 目标、消费者、产物单一，不把路由/执行/参考/留删混成总管 |
| 5 | 宿主解耦 | 不硬编码项目路线、状态或领域事实 |
| 6 | 模型解耦 | 不绑定模型、供应商或推理档位 |
| 7 | 输入输出 | 必需输入、缺口处理、固定输出和未完成状态明确 |
| 8 | 决策风险 | 默认路径先行，高风险/外发/删除/权限/提交有确认点 |
| 9 | 验证闭环 | 有最小场景，验证加载、行为和结果而非文件存在 |
| 10 | 维护成本 | 版本、证据来源和维护入口可追溯，未验证不进规则 |

### 渐进披露追加检查

11. 入口是最小路由器，引用现有 references/scripts，任务外资料不预读；12. 剔除旧模型遗留重复提醒、过慎审批和可接受的无价值条目；13. 完成证据、停止点和等待理由可观察；14. 区分常驻描述、按需正文、工具输出和交接成本；15. 大量读取/长探索/批处理若宿主支持 `context: fork`，说明隔离与回流边界。

## 第 2 步：动态验证

description、触发词、负向边界、路由、输入输出、宿主接线或运行参数变化后，准备 3–5 个场景：正向、明确不触发、兄弟 Skill 撞词、缺输入/多解、用户点名下游。观察第一跳是否正确；错误或目标不存在记 P0。行为验证分静态、运行、使用三层；配置/hook 另做运行时 dump、真实 payload、重载后真实触发。没有子代理时可人工走查，但记录原始错误和 `人工走查替代`。

## Router / Executor 追加检查

- Router：信号表命中即直达；不命中/多解按决策点提问；每条路径有近端负向边界，目标存在且可直达，默认值先于菜单，组合边对称无循环；Skill 集合或职责变化时同步更新 router，不能留下旧目标或漏掉新目标。
- Executor：失败、阻塞和重跑行为明确；外部输入先验证；产物可交接；分别报告 `passed`、`failed`、`blocked`、`not-run`。

## 第 3 步：新 Skill 设计

先不用候选 Skill 裸跑；已能稳定完成就不新建。再写设计卡（问题、用户、宿主事实、非目标、触发、输入输出、风险、验收），把项目约定/机械约束/静态知识/库级治理分流到宿主文件、hook/CI、reference 或 `asset-auditor`。只写模型猜不到且会复用的核心，长资料入 `references/`，机械动作入 `scripts/`；定义可重跑、失败状态和维护入口。宿主迁移先查官方能力、原生包和真实源码，第三方优先插件化。

把外部内容（视频、文章、他人 skill）提炼成新 Skill 时，只保留来源中的方法、流程、边界和可复用原则：触发条件写通用主题、不写单个案例（案例只放正文作可选说明）；新 Skill 独立可跑，**不添加 skill 路由、组合调用或跨 skill 依赖**，除非用户明确要求。

## 第 4 步：组合审查

检查域覆盖、共享触发词 tie-breaker、交接对称性、产物边、内部驱动边、开工链/独立工具/参考层/维护类分层，以及循环、虚空转介和重复采访。

## 第 5 步：分级与输出

P0=误路由、幻觉目标、危险动作无门或运行完全失效；P1=触发、输入输出、解耦或交接明显削弱可靠性；P2=版本、维护、测试资产等非关键缺口。输出必须包含：模式、对象/类型/路径/宿主、静态结果、动态场景与真实输出、减量改前/改后（如适用）、来源结论、P0/P1/P2、已修改、未完成状态和一个最小下一步。未有运行证据不得宣布生效；审计本身不代替用户删除。
