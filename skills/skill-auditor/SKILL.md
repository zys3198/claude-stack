# Skill 审计与设计器

本 skill 覆盖 router、executor、reference、maintenance 四类 skill。它负责判断单个 skill 是否可触发、可执行、可验证、可组合，并负责从零设计最小可用 skill；不负责替用户决定整个 skill 库的留删。

**质量底线：** 每条修复或设计建议都要绑定本地事实、官方变更、真实事故、运行输出或失败测试；没有证据就标记不确定，不把偏好写成规则。

## 核心边界

```text
Skill = 通用方法、约束、执行接口
Host files = 项目事实、路线、当前状态、完成证据
Runtime = 实际加载、调用、行为结果
```

- 项目约定放 `CLAUDE.md` / `AGENTS.md`。
- 每轮都要执行的机械约束放 hook、CI 或 linter。
- 特定任务流程、模型难猜的判断、可复用检查表才放 skill。
- 核心规则默认模型、供应商、推理档位和宿主无关；模型专属内容放 adapter。
- 自建与第三方按用户意图和安装台账判定，不按迁移目录判定。

## 模式裁决

| 用户目标 | 模式 | 首要产物 |
|---|---|---|
| 检查既有 skill | 单 skill 审计 | 静态结果、运行证据、分级问题 |
| 新建或重写 skill | skill 设计 | 触发契约、正文、测试场景、维护入口 |
| 检查多个 skill 搭配 | 组合审查 | 边界、交接、归属、循环、兜底 |
| 判断来源或重复 | 来源审计 | exact duplicate、同源替代、独立第三方 |
| 判断是否保留整个 skill | 转交 `skill-trimmer` | 留、冷、移除候选及证据 |

用户只要结论，不改文件；用户明确要求修改，才进入设计或修复。

## 第 0 步：定靶与取证

1. 确认目标路径、skill 名、宿主目录、用户目标和是否允许改文件。
2. 读目标 `SKILL.md` 全文、frontmatter、配套测试、引用它的 router 和维护文件。
3. 判断 skill 类型：router、executor、reference 或 maintenance；混合型记录主类型和混合风险。
4. 查当前会话可用 skill/tool 清单，再查本地源、安装台账、插件 payload；memory 只提供背景，不证明当前可用。
5. 记录现有用户改动和目标外文件；不覆盖、不自动删除、不自动提交。

## 第 1 步：通用静态十查

逐项输出 `PASS / FAIL / 不确定`、文件位置、证据和影响：

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 身份与来源 | name、description、目录、安装来源一致；自建、插件、同步副本可追溯 |
| 2 | description 契约 | 同时说明 what 和 when；不写步骤摘要、阶段列表或完整流程 |
| 3 | 触发边界 | 有具体正向信号和明确不用于清单；不靠“其他、等等、任何”扩大范畴 |
| 4 | 单一职责 | 目标、消费者、产物单一；不把路由、执行、参考、留删混成总管 |
| 5 | 宿主解耦 | 不硬编码项目路线、当前状态、固定课程顺序或领域事实；这些由宿主文件提供 |
| 6 | 模型解耦 | 核心不绑定具体模型、供应商或推理档位；运行时参数来自宿主能力或用户配置 |
| 7 | 输入输出 | 写清必需输入、缺失输入处理、固定输出字段和未完成状态 |
| 8 | 决策与风险 | 默认路径先于菜单；高风险、外发、删除、权限、提交等动作有用户确认点 |
| 9 | 验证闭环 | 有最小测试场景；验证实际加载和行为，不把文件存在或机制变化当成生效 |
| 10 | 维护成本 | 有版本、变更记录、证据来源和维护入口；未验证想法不进入正式规则 |

### Router 追加检查

router 型 skill 另外检查：

1. 明确信号表：具体用户信号对应具体路径，命中即直达。
2. 缺口清单：不命中或多解时，按决策点提问；不使用不可判定的“置信度闸门”。
3. 每条路由写近端负向边界；兜底写具体反问，不写空泛“问用户”。
4. 路由目标存在、可直达、归属正确；参考层和维护层不作为用户第一跳。
5. 默认值先于菜单；只有成本、风险或产物确实不同且无法判断时才提问。
6. 路由表增删绑定真实事故或官方变更；没有证据不改暴露区域。
7. 组合边对称：A 转 B 时，B 能接 A；无死循环、虚空转介或重复执行。

### Executor 追加检查

executor 型 skill 另外检查：

1. 失败路径、阻塞条件、重跑行为明确。
2. 输入边界验证存在；外部输入不直接进入命令、路径、查询或发布动作。
3. 产物可交接；下次会话不依赖聊天隐式状态。
4. 运行时错误不被成功文案掩盖；分别报告 `passed`、`failed`、`blocked`、`not-run`。

## 第 2 步：动态验证

静态通过不代表可用。以下任一变化都要跑动态场景：description、触发词、不用于条款、路由表、输入输出契约、宿主接线或运行参数。

### 触发验证

准备 3-5 个场景，至少包含：

- 正向触发。
- 明确不应触发。
- 与兄弟 skill 共享关键词。
- 输入不完整或多解。
- 用户点名下游 skill。

只给模型 description 做第一跳测试时，观察是否进正确域；第一跳错误或目标不存在，记 P0。子代理/API 不可用时可人工逐场景走查，但必须记录代理名、原始错误和“人工走查替代”。

### 行为验证

按真实症状验证，不只看中间机制：

1. 静态层：文件、frontmatter、引用和契约是否存在。
2. 运行层：skill 是否被加载、是否按输入执行、stdout/stderr 或产物是否正确。
3. 使用层：真实任务是否解决问题；没有使用数据就标记不可用，不伪造遥测。

配置、插件、hook、settings 变更必须再加：

1. dump 运行时实际配置。
2. 用真实 payload 测脚本契约。
3. 重启或重新加载后执行真实触发清单。

## 第 3 步：新 skill 设计

1. **先做反向测试**：不用新 skill 运行一次目标任务。现有能力已能稳定完成，就不新建。
2. **写设计卡**：问题、用户、宿主事实、非目标、正向触发、负向边界、输入、输出、风险、验收证据。
3. **先分流归属**：若内容是项目约定、机械约束、静态知识或整个库治理，分别移到宿主文件、hook/CI、reference 或 `skill-trimmer`。
4. **写最小核心**：只放模型猜不到且会反复复用的判断和流程；长资料放 `references/`，稳定机械动作放 `scripts/`。
5. **保持核心中立**：供应商、模型、并发、运行时参数不写死；确需专属行为，隔离为 adapter。
6. **先写测试场景**：正向、负向、边界、缺输入、组合冲突各至少一条，再写正文。
7. **设计可重跑**：重复调用不重复发送、创建、删除、覆盖或外发；已有状态可识别并跳过。
8. **定义失败输出**：工具失败、证据不足、用户未确认、目标不存在，都要停在明确状态。
9. **落版本与维护入口**：同步 `CHANGELOG.md`、`test-prompts.json` 和 `references/MAINTENANCE.md`；变更理由必须可追溯。

Pi 迁移场景先查 pi.dev/packages 现成原生包和真实源码，再决定自建；第三方 skill 优先插件化，不复制成裸本地副本。

## 第 4 步：组合审查

多个 skill 组合时，逐项检查：

1. 域边界是否覆盖，没有两不管地带。
2. 共享触发词是否有一致 tie-breaker，按最终交付物或目标裁决。
3. 交接是否对称，无循环、虚空转介、重复采访。
4. 产物边是否显式声明：A 的产物是否是 B 的输入。
5. 内部驱动边是否显式声明：B 是否已覆盖 C，用户无需重复触发。
6. 下游是否分清开工链、独立工具、参考层、维护类；参考层不作为直达终点。

## 第 5 步：问题分级与动作

| 级别 | 判据 | 动作 |
|---|---|---|
| P0 | 误路由、幻觉目标、危险动作无门、运行时完全不生效、来源误判导致错误删除 | 先停外部动作；修复后重跑受影响场景 |
| P1 | 触发边界、输入输出、宿主耦合、模型耦合、组合交接明显削弱可靠性 | 本轮修复或明确阻塞 |
| P2 | 版本戳、维护记录、测试资产、非关键表述缺失 | 本轮补齐；无证据不扩展范围 |

十查全 PASS 时只报告，不凑改动。没有运行证据时不能宣布“已生效”。涉及整个 skill 库留删或冷热分级，转交 `skill-trimmer`；本 skill 不代替用户删除。

## 输出契约

```text
模式：审计 / 设计 / 组合审查 / 来源审计
对象：名称、类型、路径、宿主
静态结果：通过项数、失败项、证据位置
动态验证：场景数、真实输出、跳过原因
来源结论：自建 / exact duplicate / 同源替代 / 独立第三方 / 不确定
P0：无，或逐条列出
P1：无，或逐条列出
P2：无，或逐条列出
已修改：文件列表；未授权时写“未修改”
未完成：blocked / not-run / 待用户确认
下一步：一个最小动作
```

## 反模式

- 只看 `SKILL.md` 写得漂亮，不跑真实触发。
- 只按同名或哈希删除 skill，不查台账、插件 payload 和来源。
- 把迁移路径当自建来源。
- 把项目事实、当前课程路线、固定状态写入通用 skill。
- 把具体模型名写进核心规则。
- 用“置信度”替代可查的信号表和缺口清单。
- description 写完整流程，诱导模型跳过正文。
- 无证据顺手改路由、扩触发词或增加检查项。
- 把“已配置”“脚本正确”“文件存在”报告成“运行已生效”。
