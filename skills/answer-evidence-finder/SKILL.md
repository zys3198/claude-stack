# Answer Evidence Finder — 回答依据提取器

你的任务：给定一个问题 + 一批相关文章文件路径，从文章中提取与问题直接相关的原文片段，作为回答依据。

## 核心原则

- **精准**：只提取与问题直接相关的片段，不摘录无关段落
- **原文**：返回原文，不总结不重写不翻译
- **完整**：片段要保留足够上下文，能独立支撑回答，不截断到读不懂
- **标注来源**：每个片段标注出自哪个文件
- **不回答**：只找依据，不生成答案

## 触发条件

满足以下任一条件时使用此 skill：
- 用户提出问题，并提供了一批文章路径要求从中找回答依据
- 与 doc-finder skill 配合使用：doc-finder 找到文章列表后，用此 skill 提取依据
- 用户说"从这些文章里找 X 的答案"、"帮我提取相关内容"等

## 工作模式

### 模式判断

根据文章数量和总篇幅选择模式：

| 条件 | 模式 |
|------|------|
| 文章 ≤ 3 篇，每篇 ≤ 200 行 | **单智能体顺序读取** |
| 文章 > 3 篇 或 总行数 > 600 行 | **多智能体并行查找** |

判断方法——先快速评估：

```bash
wc -l <file1> <file2> <file3> ...
```

### 单智能体模式

适合少量短文。顺序读取每篇文章，用 grep 定位相关段落，提取片段。

### 多智能体并行模式

适合大量长文。按以下规则分组派智能体：

**分组策略**：
- 每个智能体负责 1-3 篇文章（按文件相关性分组，同主题放一组）
- 每个智能体收到的指令包含：问题 + 分配的文件路径 + 输出格式要求

**智能体指令模板**：

```
你是一个回答依据查找器。

问题：<用户的问题>

请在以下文章中找到与问题直接相关的原文片段。

文章列表：
- <file_path_1>
- <file_path_2>

要求：
1. 读取每篇文章
2. 用 grep 或内容搜索定位与问题相关的段落
3. 提取原文片段，保留足够上下文（前后各 3-5 行）
4. 每个片段标注来源文件和行号
5. 只返回与问题直接相关的内容，不返回无关段落
6. 如果某篇文章没有相关内容，注明"无相关内容"

按以下格式返回：
```
### <文件名>

**行 L1-L2：**
> 原文片段
> …

**行 L3-L4：**
> 原文片段
> …
```
```

**合并结果**：所有智能体返回后，合并去重（不同智能体可能命中同一段落）。按文章路径顺序排列输出。

## 提取技巧

### 定位方法

对每篇文章，组合使用以下方法：

1. **关键词 grep 定位**
   ```bash
   grep -n -i -C 5 "<keyword>" "<file>"
   ```

2. **标题扫描** — 文章中的 `##` / `###` 标题经常直接对应问题主题，先扫标题再定位
   ```bash
   grep -n "^#" "<file>"
   ```

3. **全文快速浏览** — 短文章（< 100 行）直接读全文，比多次 grep 更快

### 提取粒度

- **问题问的是"是什么"** → 提取定义段落、概念解释
- **问题问的是"怎么做"** → 提取步骤、配置、代码示例
- **问题问的是"区别/对比"** → 提取对比表格、差异说明段落
- **问题问的是"为什么"** → 提取原因分析、原理解释
- **问题问的是列表/分类** → 提取列举段落，保留完整列表项

### 上下文保留

提取片段时：
- 保留标题层级（`##` / `###`）让片段可定位
- 代码块完整保留，不截断
- 列表项完整保留，不中途截断
- 如果关键段落跨越多节，合并提取，标注行号范围

## 输出格式

```
## 回答依据：<问题简述>

以下片段来源于 <N> 篇文章。

---

### [文章标题](文件路径)

**行 L1-L2：**
> 原文片段内容
> …
> …
> …

**行 L3-L4：**
> 原文片段内容
> …

---

### [文章标题](文件路径)

**行 L1-L2：**
> 原文片段内容
> …

---

共提取 <M> 个相关片段。
```

如果某篇文章无相关内容，在输出中注明：

```
### [文章标题](文件路径)

无直接相关内容。
```

## 注意事项

- 片段不重叠：如果两个关键词命中同一段落，只提取一次，取更完整的上下文范围
- 不要为了"凑数"而提取弱相关内容。没有就直接写"无相关内容"
- 代码示例完整保留，包括注释
- 表格完整保留，不截取部分列
- 如果文章有 YAML frontmatter，跳过不提取（那是元数据不是内容）

## 执行检查点

### 🔴 STOP — 文件可达性检查

开始提取前，验证所有文件路径存在：
- 全部存在 → 继续
- 部分不存在 → 报告哪些缺失，对存在的文件继续提取
- 全部不存在 → 报错退出

### 🔴 STOP — 提取结果非空检查

提取完成后：
- 有 ≥ 1 个片段 → 输出结果
- 所有文件均"无相关内容" → 明确告知用户，不编造弱相关内容凑数

## 失败模式处理

| 场景 | 触发条件 | 处理 |
|------|---------|------|
| grep 无结果 | 关键词未命中任何文章 | 扩大搜索范围：用同义词/英文/缩写重试 |
| 文件编码错误 | 读取报 UnicodeDecodeError | 尝试 UTF-8 → GBK → Latin-1 顺序重试 |
| 多 Agent 去重冲突 | 不同 Agent 命中同一段落 | 取行号范围更大的那个片段，标注合并来源 |
| 文章过长 agent 超时 | 单篇 > 500 行导致读取超时 | 分段读取，每段独立搜索 |
| 用户问题模糊 | 无法确定搜索关键词 | 先向用户确认问题核心，再开始提取 |

## 不要做什么（反例清单）

| # | 反模式 | 正确做法 |
|---|--------|---------|
| 1 | 回答用户的问题 | 只找依据不回答，用户会自己综合 |
| 2 | 总结或重写原文 | 返回原文片段，保持原始表述 |
| 3 | 翻译外文内容为中文 | 保留原文语言 |
| 4 | 凑数提取弱相关内容 | 没有就直接写"无相关内容" |
| 5 | 只搜文件名不搜内容 | 必须同时搜文件名和文件内容 |
| 6 | 跳过可达性检查直接搜索 | 先验证文件存在再开始 |
| 7 | 修改原文中的代码格式 | 代码块完整保留原样 |
