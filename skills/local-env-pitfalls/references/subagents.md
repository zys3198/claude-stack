## 状态分三步核验

启动结果、运行状态、完成通知各算一次，不能相互顶替：

- 只有收到工具的成功**启动**结果，才能说子代理已启动。
- 只有收到**完成**通知并读取报告，才能说工作已完成。
- **失败通知优先覆盖先前的启动状态**：收到失败通知后立即停止引用旧状态，缩短提示词或重新启动新代理。曾把启动请求成功当成持续运行状态，实际任务已因提示词过长失败。

## 失败后先诊断，不原样重试

- worktree 子代理返回基准分支解析失败后，**先诊断前置条件**，禁止原样重试同一调用——没有新增证据，也不推进核查。首次失败即检查实际分支与隔离需求；只读任务改用宿主支持的非 worktree 路径。
- **换代理名称、模型、类型，或在 prompt 里写「不要 worktree」，都不算改变了工具隔离参数**。`isolation: remote` 也曾返回同一错误，不能称为本地非隔离调查。
- 没有可用的非隔离入口时，立即在主线程只读调查，不再试其他代理。
- 不把启动失败计作复核完成，不为只读核查创建或修改 Git 引用。

## 其他

- **子代理流解码失败时先确认服务状态**，不要反复堆叠重试。
- **权限分类器可能拒绝 `git worktree remove`**：`git branch -d` 通常可以通过；删除工作树需要用户放行，或由人在终端自行执行。
