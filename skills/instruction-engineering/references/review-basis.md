# 审查基准：垫在检查表之下的六条判据

九项检查可直接执行；本文件是它们背后的判据，用来在两项互相冲突或拿不准时定夺。原文整段搬自 `SKILL.md`。

**两个负担**。每份新增文档和指针都花掉两种成本之一。**context load** 是常驻材料压在模型窗口上的成本：`CLAUDE.md` 里的一行、一个 skill 的 description，只要在上下文里，无论这次用不用得上，每一轮都花 token 和注意力。**cognitive load** 是压在人身上的成本：有哪些文档存在、什么时候该拿哪一份。人就是索引，这份成本不要求压到最小，它是人保留判断权的代价，把无关紧要的地方减掉即可。指针后面的材料靠指针那一行逃脱 context load，没有指针的材料完全压在 cognitive load 上。遇到位置判断时问一句：这次要付哪种成本。十次里只有一次用得上的规则，另外九次都在付 context load。

**信息层级**。文档由两类内容组成，**步骤**（agent 按顺序做的动作）和**参考**（按需查阅的定义、规则、事实），两者自由混合。每一块内容落在三级阶梯的哪一层，是核心判断：

1. **文件内步骤**——主层，agent 做什么，按顺序。
2. **文件内参考**——按需查阅。平铺的一批同级条目（一次审查的全部规则）是正常排列。
3. **被披露的参考**——推到另一个文件，靠 context pointer 抵达，指针触发时才载入。

往下推叫 **progressive disclosure**：把内容推出主文件、放到指针后面，让顶层保持好读。推得太少顶层膨胀，推得太多就把 agent 真正需要的材料藏起来。分支是最好的披露判据：每条分支都要的留在文件里，只有部分分支会走到的推到指针后面。拆一次就多付一份负担，所以只在切法值这个成本时才拆，两种切法各自成立：**按分支拆**，让每条路径只带上自己要的材料；**按顺序拆**，一串步骤里靠后的那些会诱使模型赶当前这一步，把它们挡在视野外能逼出更多实际工作——反过来，把两段顺序并进一个文件，会让每一步都看见后面还有什么，诱发过早完成。文档带步骤时，本该披露的文件内参考会盖住步骤，让「要不要照步骤做」变成掷硬币，这既是可读性问题，也让不同次运行走出不同结果。

**正面陈述**。用禁止来引导会把被禁的行为拖进上下文，让它变得更可得（「别想大象」）。禁令是一个弱的修饰语，被强激活的那个概念会压过它，半读成一条去做这件事的指令。要写出**正面的目标**（「写单行注释」），被禁的那种写法就不必出现。审查时看到一条禁令，先问能不能改成正面陈述：不能改的只有无法正面表达的硬约束，即便如此也配上正面目标，让注意力落在该做什么上。

**锚定词**。模型预训练里已有的紧凑概念拿来做锚点，它每出现一次就累积一层分布式定义，用最少的 token 锚住一整片行为（lesson、fog of war、tracer bullets 这类）。生造词也能用，但定义成本要用真词白送的先验去换，能找现成词就找现成词。审查时找展开的表达：同一个意思在三处各写一句、一个指针花一整句去比划一个概念，都是该收成一个词的信号。词的分量也要核：打不过模型默认行为的弱词跟没写一样（模型本来就比较仔细时写「要仔细」），修法是换一个更重的词，重到能把默认行为撬动为止，换别的写法没有用。

**context pointer**。指针是上下文里指着某份外部材料的那句话，它同时说明材料是什么、以及哪些分支该去取它。触发可靠性由指针的**措辞**决定，不由目标决定：该用的材料挂在措辞太弱的指针后面是稳定性缺陷，先把措辞改准，改不动才考虑把材料搬回正文。指针写多显由依赖的强度决定：没有它输出就是**错的**（硬依赖），写一句显式指针；没有它输出只是**不够锐利**（软依赖），一句模糊的散文提及就够——把软依赖写成硬依赖的措辞属于过度承重，既白占每轮的常驻开销，也把不承重的指针撒得到处都是。每条分支配一个触发词，指同一件事的同义词算一条分支写了两遍；指针里不重复正文已经交代过的身份。

**归置相邻**。同一概念的定义、规则和注意事项放在同一个标题下面，读一处就带出邻居。它与重复是两件事：重复把一个意思写在两处，散落把一个意思拆到多处。判据是「读起来像一份给 agent 写的说明」——成组的材料像，散落的材料不像。

## 九项检查操作参考

| 检查项 | 操作标准 |
|---|---|
| 触发边界 | 列具体正向信号和近端负向边界；不把领域相关、单个关键词或“任何/其他/等等”当成无条件触发。 |
| 重复与冲突 | 为每条规则保留一个权威位置；不同文件的优先级、例外和动作一致。发现两个都成立的冲突并列交用户，不自行取舍。 |
| 资料读取 | 只有会改变当前判断、执行或验收的材料才读；任务外材料按需路由。 |
| 等待边界 | 每个等待点写风险、权限或用户决策理由；安全且明确的动作可继续。 |
| 完成标准 | 写可观察证据、停止点和失败/阻塞状态；文件存在、配置声明或“已执行”不是生效证据。 |
| 留存依据 | 规则能说明保留理由；源码一眼可见、通用最佳实践、一次性修复和冗长解释列为候选。 |
| 常驻划分 | 只有每轮必须生效、或应由 hook/CI/审阅者固定执行的内容常驻；特定任务资料按需加载。语言风格、证据门槛和交付自检不得移走。 |
| 逐句剪除 | 对保留内容做 no-op 检查；识别 duplication、sediment、sprawl、relevance，整句删除无行为影响的内容。 |
| 时效核对 | 核对文件、命令、版本和目录仍存在且可用；会随环境变化的具体事实移出常驻文件或改为权威指针。 |

## 证据与输出补充

审查结论分 `[源码]`、`[执行记录]`、`[官方原则]`、`[规则推测]`、`[未知]`；静态文字不能证明运行行为。每条 FAIL 的最小报告应包含位置、原文、场景、证据类型、影响、unified diff 和保留的安全/权限/业务/验收约束；全部通过时写「无须修改」。
