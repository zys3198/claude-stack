# Skill Trimmer — Skill 库精简判定

强模型时代，skill 的收益是「沉淀模型猜不到的东西」，成本是「路由噪声 + 描述上下文 + 互相抢活」。本 skill 把「哪些留、哪些删」变成可复用的判定流程，而不是每次凭感觉重想。

**本 skill 是「文章基准 + 本机先例」的融合版，不是纯文章转写。** 判定依据分三层——`【文章】` 来自 JavaGuide《再见 Superpowers！很多 Skill 真的可以扔掉了》(2026-07-23)；`【Carl】` 来自程序员Carl《再见Superpowers！恭喜还没用这些skill的朋友们！现在不用学了！》(2026-07-28, mp.weixin.qq.com/s/pxf-OlkuKNBmP4sbfpEMCw)；`【本机】` 来自你 2026-07-23 审计先例 + 2026-07-25 你亲口拍板的 3 条冲突决议。两层文章一致处直接判；Carl 的增量是「四删五留」分层（见核心立场第 4 条）——它把 JavaGuide 的「三类留 + D 类删」细化为可操作的删除/保留清单。3 个曾有的冲突点你已拍板（见「已定冲突」），不再呈分歧、直接按决议判。

## 核心立场（先立住，再判定）

**【文章】基准判据（JavaGuide）：**
1. **砍 skill 的收益是减路由噪声，不是省 token。** skill 不触发就不加载正文，描述列表才常驻。删的目标 = 减少误路由和描述列表膨胀，不是省磁盘。
2. **只留三类 skill**（判据细节见 `references/retention-rubric.md`）：
   - **A 偏好沉淀**：模型猜不到的个人/项目固定产物——文风、图表规范、模板、发布流程。
   - **B 专业判断+脚本/资料**：安全审查、复杂文档处理、框架迁移、生产检查——带 checklist、脚本、证据源。
   - **C 方向纠错**：防开工走错方向（如 grill-me 式追问）。模型越强执行越快，走错方向代价越大，这类最难被替代。
   - 反面即删：**D 流程步骤型**——只提醒「先读项目、再写代码、最后跑测试」的，强模型本来就会做，零增量信息。
3. **套件流程型要重审启用时机（文章主论点）——但 Superpowers 套件你已拍板不审（见决议 #3），本条只对「其他套件 / 散装流程型 skill」生效。** 流程完整性 ≠ 价值：brainstorm→plan→TDD→worktree→subagent→review 全套，对复杂/陌生/高风险改动有价值，对小改动是从保护变负担、白烧 token。判定**非 SP** 套件或散装流程 skill 时加问一句：**它的启用时机有没有写清？小任务会不会被它拖着走全流程？** 时机模糊 → 标「过度流程」候选。

**【Carl】增量判据（2026-07-28，四删五留）：**

4. **四类最先没必要（删除清单细化）**——命中任一即进删除候选，与 D 类并列：
   - **C1 提醒认真型**：全部价值=把正确废话写长（先思考再回答/写完要检查/遇到问题找根因）。把「修复后相关测试必须通过」写进验收标准，比加载几百行「如何成为严谨工程师」更有效。
   - **C2 重复 Harness 原生能力**：计划、子Agent、代码审查、浏览器、测试、工具调用已是 Codex/Claude Code 原生能力。Skill 只包一层 → Harness 想推进 / Skill 要求先进规划仪式 / 项目规则又要另一套验证顺序——三套流程打架，模型忙着判断听谁的。这是 Carl 相对 JavaGuide 最锋利的增量：**判 D 类时加问一句「这是不是把 Harness 原生能力又包了一层？」**
   - **C3 一刀切重流程**：改错别字也 brainstorming、修小 bug 也写完整设计、动两行 CSS 也拉子 Agent 实现+双 Agent 审查。任务复杂度不同，流程强度应不同。
   - **C4 从没被评测过的 Skill**：收藏 Skill 像收藏 Prompt 模板，装完从没对比过成功率/返工次数/token 耗时/误触发/是否过度流程化。没有失败样本也没有对照评测 = 赛博护身符，不是工程资产。
5. **五类继续保留（保留清单细化）**——与 A/B/C 类互补，判定保留时先查这五类：
   - **K1 项目专属规则**：公司目录、发布规范、业务口径、历史约定——模型不知道。
   - **K2 确定性脚本**：PDF 渲染、图片压缩、数据迁移、制品打包——不能只靠模型「理解」。
   - **K3 外部工具与连接**：数据库、内部文档、设计工具、审批系统——需要真实接口与权限。**这是 Carl 新增的保留类，JavaGuide 没有单列。**
   - **K4 高风险流程**：上线、付款、删库、权限变更——需要硬边界和人工确认。
   - **K5 失败样本沉淀**：模型在同类任务上稳定犯错，才值得把纠错方法固化——与 JavaGuide 第 4 条「反复翻车」一致。
   - 一句话分层：**通用常识交给模型，组织经验留在 Skill，安全边界交给系统。**
6. **默认顺序反转：先裸跑，再补最小 Skill。** Carl 主论点：不要先装一大包 Skill 再用 Agent；先让模型直接做，它真做不好再补一个最小 Skill。判定时的用法：评估一个 skill「值不值得留」时问——**它解决的是可复现的失败，还是想象中的失败？** 只解决想象中的失败 → C4 候选删。
7. **同一地方反复翻车、且翻车代价不低，才值得单独留/写一个 skill。**（JavaGuide 兜底判据，与 Carl K5 一致。）

**本机叠加规则（用户已拍板，2026-07-25）：**
8. **被 router 引用的 D 类 → 删 skill + 顺手改路由。** 理由：skill 真没用，引用它的路由那行也该改。判定动作：标「移除+改路由」，移动后必须同步修掉 router/CLAUDE.md 里对应引用（交 guide-skill-auditor 或手动），不留死引用。不再是免死牌。
9. **E 类（流程型）留兜底。** 你按任务分级用模型：弱模型 + 复杂任务时流程型是兜底。流程型**不一刀切删**，只有「D 类 AND 零引用 AND 无资产」才进移除候选。
10. **Superpowers 套件不审。** 整个 SP 套件豁免启用时机审查，不进「过度流程候选」，默认全留。（你已定：不审。）
11. 🔴 **分类建议必须用户拍板，AI 不自动执行移除。**（2026-07-23 先例；执行细节见流程第 4 步 CHECKPOINT。）

## 本机环境事实（判定前必读，别再探一遍）

- **skill 两种形态**：`~/.claude/skills/` 下大部分是**软链**（指向 cc-switch 源 `~/.cc-switch/skills-*` 等），少量是**直管目录**（实体文件）。软链删的是链接，**源还在，可恢复**；直管目录删了就是真删。软链里又分两亚型——junction（目录联接，Python 可读目标）和真符号链接（msys `/c/...` 目标，Windows Python 读不出，inventory 里标 `unresolved`）；`scan_skills.py` 已统一处理，判定时把 `unresolved` 当软链看待即可。
- **移动 = 断链/移目录，不是删除。** 候选移入 `~/.cc-switch/skills/_weak-model-backup/`（已有先例，夹内 README 记标准）或 lab-area exp 目录。恢复走 cc-switch 官方 `RESTORE_SYMLINKS.md` 机制（Python `os.symlink` + msys2 路径），**Windows 下不手搓 symlink、不 copy**——这是 §9 规则的既定例外。
- **插件 skill（`ecc:*` 等整包）不在本 skill 判定范围**——插件是整包开关（`enabledPlugins`），用户已拍板全开，不逐个评。
- **`~/.claude/skills/learned/` 是 ai-coding-coach 产出区**，属 A 类偏好沉淀，默认保留，不进候选。

## 判定流程

### 1. 盘点

跑清单脚本（只读，列出所有 skill + 来源 + 是否软链）：

```bash
python ~/.claude/skills/skill-trimmer/scripts/scan_skills.py
```

输出 → `skill-trimmer-workspace/inventory.json`（workspace 建在 skill 目录旁，避免污染）。拿到清单后按 description 分组：写作 / 编码 / 前端 / 学习 / 绘图 / 运营 / 元管理 等。

### 2. 引用扫描（记录引用方，非免删）

对**每个候选 skill 的名字**，grep 它被谁引用：

```bash
grep -rl "skill名" ~/.claude/skills/ ~/.claude/CLAUDE.md ~/.claude/projects/*/memory/ 2>/dev/null
```

- 记录下来：**引用方清单**（哪个 router / 哪个 skill / CLAUDE.md 哪行）。这一步不再是「免删名单」，而是「改路由清单」——
- 按决议 #1：被引用的 skill 若判定为「没用（D类）」→ **删 skill 且必须同步改掉这些引用**，不留死引用。引用方清单就是移动后要逐一修的清单。
- 被引用的 skill 若判定为「有用（A/B/C 类）」→ 保留，引用不动。

### 3. 逐个判定（四维 + 触发面）

对过筛的 skill，逐个问（详细判据与示例见 `references/retention-rubric.md`）：

| 维度 | 问法 | 指向 |
|------|------|------|
| 增量信息 | 模型（Fable 5 级）本来就会做吗？有没有项目特有约束/脚本/模板/检查项？ | 只会常规步骤 → D 类候选删 |
| 资产 | 带 scripts/ references/ assets/ 模板吗？ | 有 → 偏 A/B 留 |
| 偏好/方向 | 沉淀个人固定产物？或防开工走错方向？ | 是 → A/C 留 |
| 使用面 | 过去用到过吗？同一个坑翻过吗？翻车代价高吗？**【Carl】有没有评测对照——成功率/返工次数/token 耗时有没有量过？** | 反复翻车+代价高 → 留（K5）；从没用过+D 类 → 删；从没评测过 → C4 候选删 |
| 套件时机 | 属**非 SP** 套件/散装流程型吗？启用时机写清了吗？小任务会被拖全流程吗？（SP 套件按决议 #3 跳过本行）**【Carl】是不是一刀切重流程（C3）？** | 时机模糊+拖全流程 → 「保留-流程兜底」，仅标注不删 |
| Harness 重复 | **【Carl】这个 skill 是不是把 Harness 原生能力（计划/子Agent/审查/测试/工具调用）又包了一层？**（C2） | 是 → 三套流程打架，进删除候选 |
| 触发面 | description 写得宽不宽？会不会和普通改动抢路由？ | 太宽 → 不删也应收窄描述（转 guide-skill-auditor / darwin-skill） |

判定结果七档：
- **保留**：A/B/C 类，或反复翻车兜底。
- **保留-流程兜底**：流程型/E 类——按决议 #2 留兜底，不审。
- **保留-SP套件**：Superpowers 套件成员——按决议 #3 豁免，不审。
- **移除+改路由**：D 类且没用，但被 router/CLAUDE.md/其他 skill 引用——按决议 #1 删 skill，同时列出引用方清单，移动后逐一修掉引用（交 guide-skill-auditor 或手动），不留死引用。
- **收窄描述**：能力该留但触发面太宽抢路由——问题在 description 不在能力，改描述而非删。
- **移入备份**：D 类 AND 零引用 AND 无不可替代资产。移 `_weak-model-backup/` 不删。
- **删前用户确认**：拿不准的、有资产但疑似用不上的、疑似重复能力的——列出证据让你定。

### 4. 报告 + 拍板

输出一张表（≤5 项一组，超出拆「建议移动 / 建议收窄 / 拿不准待你定」）：

```
| skill | 分类 | 判定 | 关键理由 | 引用情况 |
```

🔴 **CHECKPOINT · 🛑 STOP**：**AI 只出建议表，绝不自动移动/删除任何 skill。** 停在这里等用户逐项拍板。用户逐项确认后，移动动作才执行（移动属「文件删除」级人工确认线）。未获明确「确认/按推荐来」前，不执行任何 `mv`/`rm`。

- 执行移动用 `mv` 到 `_weak-model-backup/`（软链）或 lab-area 备份（直管目录），并在备份夹 README 追加一行：skill 名 / 判定分类 / 移动日期 / 理由。

**失败对策（if-then，缺失时的兜底）**：

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| `_weak-model-backup/` 不存在 | 先 `mkdir -p` 建夹再移 | 建不了就移 lab-area `exp/<日期>-skill-trim/` |
| 移动的 skill 被引用，但改路由时找不到引用行 | 重跑第 2 步引用扫描定位最新行号 | 仍找不到 → 报告用户「引用已失效/在非常规位置」，不擅自猜改 |
| 断软链后 router 报 skill 找不到（死引用） | 用 guide-skill-auditor 扫死引用并修 | 修不掉 → 用 cc-switch `RESTORE_SYMLINKS.md` 恢复软链，回滚本次 |
| 移动后用户反悔 | 从 `_weak-model-backup/` 移回 / 重建软链 | 直管目录从 lab-area 备份 `cp` 回 |
| grep 引用扫描零结果但怀疑漏 | 换 word-boundary + 连字符变体再扫一遍（`review` vs `code-review` 坑） | 仍零 → 标「零引用（已双扫）」再进移除候选 |

## 红线（不要做）

- 不把「路由引用」当免死牌，也不删了 skill 留下死引用——被引用的 D 类走「移除+改路由」，移动后必逐一修掉引用方（决议 #1）。
- 不删流程型/E 类（除非零引用+无资产的纯 D 类）——弱模型兜底（决议 #2）。
- 不审 Superpowers 套件——整个豁免（决议 #3）。
- 不动插件整包（ecc 等）、不动 `learned/`。
- 不在没有引用扫描的情况下直接判定删除——引用扫描是「改路由清单」，省不得。
- 不把「看起来没用」当证据——判据必须是分类 + 引用 + 资产，三样俱查。
- 不混淆三层判据——报告里每条理由标清是【文章】（JavaGuide）/【Carl】还是【本机决议】。

## 附录：用户贴文章 URL 时的抓取顺序（2026-07-28 失败样本沉淀）

用户贴「skill 断舍离」类文章 URL 要求落地时，先抓内容再判定。抓取按序降级，别在一棵树上吊死：

1. **WebFetch** 先试——通用网页最快。
2. **微信公众号必撞验证码**（`环境异常/完成验证后即可继续访问`）——WebFetch 拿不到正文，直接跳第 4 步。
3. ~~agent-reach 的 Exa / web-reader MCP / Camoufox~~——本机 2026-07-28 实测全断：mcporter 无 exa/web-reader server、Camoufox 缺 `camoufox` 模块、Jina Reader 匿名档被 IP 封（401）。别浪费轮次重试。
4. **Playwright MCP 直接打开 URL**（`browser_navigate` + `browser_snapshot`）——真实浏览器能过验证码拿全文，snapshot 存 `~/.playwright-mcp/page-*.yml`，大文件用 Read 分行读。公众号文章实测有效。
5. 拿到全文后提取：核心立场、删除判据、保留判据、与现有基准（JavaGuide/本机决议）的**增量**——只把增量融进判定层，不整篇转写。

## 与其他 skill 的分工

- **guide-skill-auditor**：审 router 型 guide 的质量/误路由/抢单——它管「router 健不健康」，本 skill 管「库里哪些该留」。精简后若发现 router 引用了被移 skill，用 guide-skill-auditor 修 router。
- **darwin-skill / skill-creator**：优化单个 skill 的内容与描述。本 skill 判定「收窄描述」的，交给它们改。
- **skill-creator**：判定结果是「这个坑没有 skill 兜、值得新建一个」时，走它。
