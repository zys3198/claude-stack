# Goal Run — 目标自动续跑

用户说「/goal <目标>」或「自动续跑直到 X」时进入本模式。目标明确后才进入，
模糊目标先用 AskUserQuestion 压清。

## 入口契约

进入时先向用户复述并固化 4 项，写入任务清单（TaskCreate）：

1. **目标**：一句可验收的话
2. **成功标准**：可证伪的完成信号（贴证据即可停）
3. **预算**：最大轮数（默认 25）、token 上限（默认 100k）、单轮最长时长
4. **阻塞预案**：可能卡住的点 + 对应 goal_wait/goal_blocked 处理

## 循环行为

- 每完成一个工作步，到空闲边界（无 pending 工具、无待读文件）时用
  `ScheduleWakeup` 自续（默认 1200s，外部状态变化快时按实际节奏 270s~3600s），
  `prompt` 传回本轮目标与进度摘要，`noop` 按是否产出新内容填。
- 每轮先读上一轮留下的状态（任务清单/计划文件），不重头再来。
- 外部进程（CI/构建/下载）用 `run_in_background` + `Monitor` 等通知，不空转轮询。

## 三终结工具（语义，非实体工具）

| 终结 | 触发 | 动作 |
|------|------|------|
| goal_complete | 成功标准达成 | 贴证据摘要（做了什么/验证命令/输出），停止自续 |
| goal_blocked | 连续 3 轮无实质进展 | 停止自续，报告「已知什么/哪些假设被证伪/缺什么证据」，问用户 |
| goal_wait | 卡在外部依赖 | 记录依赖+截止时间，ScheduleWakeup 到截止点，到点仍不可用则转 goal_blocked |

## 安全上限（不可逾越）

- 最大 25 轮，超出即停并汇报
- 连续 3 轮无进展立即暂停（goal_blocked），不「再试试」
- 累计 token 超预算即停
- 每次自续都检查这三条，任一触发即终止

## 汇报格式

- goal_complete：`已完成 <目标>。验证方式：<命令+输出摘要>。` 不埋在回顾里
- goal_blocked：`卡在 <点>。已知：<X>。假设被证伪：<Y>。缺：<Z>。下一步要你定。`
- goal_wait：`等 <依赖>，截止 <时间>，到点自动检查。`
