# 工具链坑位清单

每一条都来自实际踩过的坑，带上当时的判据。按主题查对应小节。

## 路径与引号

- **Git Bash 会改写环境变量里的路径**：调用 Windows 工具时，形如 `/foo` 的环境变量值被自动翻译成 Windows 路径。传根相对值（URL 路径、容器内路径、正则）时，用 `MSYS_NO_PATHCONV=1` 或双斜杠前缀保护。
- **Bash 外层双引号会提前展开 `$变量`**：调 PowerShell 时变量被 Bash 吃成空值，脚本里表现为莫名的空值错误。改用单引号包裹，或写成独立脚本文件再执行。
- **外层双引号内的代码片段先当字符串看一遍**：确认哪些符号会在到达目标解释器之前被外层 shell 处理掉。

## 编码与输出

- **Windows 原生命令按系统代码页输出**：`netstat`、`tasklist` 这类命令的输出直接按 UTF-8 解码会得到乱码。读取前先确认代码页，或改用 PowerShell 的对应命令。
- **Python 打印非 ASCII 内容前先设编码**：Windows 上标准输出默认按系统代码页编码，中文会报错或乱码。脚本开头执行 `sys.stdout.reconfigure(encoding="utf-8")`。
- **读写文件显式指定 `encoding='utf-8'`**，不依赖系统默认。
- **PowerShell 5.1 把无 BOM 的脚本当 ANSI 读**：脚本里出现非 ASCII 字符会导致解析失败并报出与真实原因无关的语法错误。要么只写 ASCII，要么保证 BOM。

## 脚本与解析

- **超长内联命令会被解析器截断**：长 heredoc 和超长单行命令在 Git Bash 上会解析失败。超过一屏就写成文件再执行。
- **CMD 包装器不是原生可执行文件**：`npm`、`pnpm` 在 Windows 上是 `.cmd` 包装器，不能直接当可执行文件传给 `subprocess`。先单条验证调用方式，再写进脚本。
- **f-string 里不要复用外层引号**：Python 3.12 之前会直接语法错误。复杂条件先算成局部变量再插值。
- **批量编辑工具省略空的可选字段**：空的 `queries`、`handle` 之类传空值会解析失败，直接省略。
- **短文件的读取偏移量写多一位就返回空**：改用内容检索或精确切片。
- **同一批里做过结构改动之后要重新定位**：行号已经位移，沿用旧行号的后续操作会落在错误位置。

## 工作树与子代理

- **建工作树或克隆之前先扫同级目录**：确认 `git worktree list` 和同级检出里没有同一件事的副本。
- **工作树被 `core.worktree` 重定向会导致启动失败**：发现后先核对 `git config core.worktree`，不要反复更换隔离方式。
- **隔离工作树里动态生成的脚本可能被钩子拒绝**：钩子判定不可信即拒绝执行，改用原生文件编辑工具。
- **远程隔离看到的可能是另一份检出**：远程执行得出的结论必须回本地核对未提交状态。
- **shell 超时之后先确认子进程**：Windows 上超时不会终止已派生的 git 进程，它会继续持有锁文件。继续操作前先确认进程和仓库状态。
- **Windows 上父进程退出不连带终止子进程**：自己启动的进程必须按 PID 精确终止，否则会占住端口和文件锁，阻塞后续会话。
- **子代理流解码失败时先确认服务状态**，不要反复堆叠重试。
- **查分支、提交、MR 引用和冲突状态优先用 Git**，不要从页面或缓存判断。
- **权限分类器可能拒绝 `git worktree remove`**：`git branch -d` 通常可以通过；删除工作树需要用户放行，或由人在终端自行执行。
