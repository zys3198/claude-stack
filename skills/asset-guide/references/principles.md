# 资产原则

日期：2026-09-27 | owner：用户

## 原则

### 表达层 —— 怎么写

| # | 原则 | 判据 |
|---|---|---|
| A1 | 协议化 | 协议 > 文字，schema > 散文 |
| A2 | 结构化 | 固定标题、固定字段 |
| A4 | 命名有语义 | 目录载分类、文件载身份、日期／状态词载时间；引用使用稳定 id |

### 组织层 —— 放哪

| # | 原则 | 判据 |
|---|---|---|
| B4 | 引用 > 复制 | 一知识一源，其余指针 |
| B6 | 加载形态归类 | 每类资产落下面「加载形态」四格之一 |

### 治理层 —— 怎么活

| # | 原则 | 判据 |
|---|---|---|
| C1 | 显式契约 | 触发／输入／输出／权限／失败写清 |
| C2 | 最小权限 | 密钥不入库；工具、网络、写文件显式 |
| C3 | 可验证 | 能机械判的写检查器，判不了的写判据并标明 |
| C4 | 生命周期 | owner／updated／过期；废弃归档 |

**A3 符号化、B1 渐进披露、B2 集中索引、B3 单一事实源、B5 只放必要 五条不在此复述**——文档怎么写、怎么分层、怎么剪除，见 `/writing-for-agents`。

## 示例

每条一个正例、一个反例，都取自本机实物。反例只标出问题，不在此改——改动走各自的确认线。

**A1 协议化**
- ✓ `docs/protocols/gate.md` 把门禁写成四个固定字段，`hooks/scripts/authorization_scope.py` 逐字比对：协议可执行、可核对
- ✗ 散文式授权描述「在合适的时候取得授权」——判据靠每次重新解读

**A2 结构化**
- ✓ 台账现状表固定六列（名称／状态／位置／出处／恢复／备注），没有内容的格子留空也占位
- ✗ 同一种资产混着自然段、无序列表、表格三种写法，机械检查要写三套解析

**A4 命名有语义**
- ✓ `backups/ai-product-development-removal-2026-09-27/`：主题与日期都在名里，恢复路径不必查表
- ✗ `installing/skill-install.md:17` 指向已不存在的 motrix——引用没跟上游改，死引用没人发现

**B4 引用 > 复制**
- ✓ `asset-guide` 的写作判据整段转指 `/writing-for-agents`，本文件零副本
- ✗ `dev-clean` 与 `dev-status` 重复同一段 141 字符命令块——`protocol_check.py` 的「重复」判据实测命中，改一处漏一处

**B6 加载形态归类**
- ✓ 无 `paths` 的 `rules/*.md` 即常驻、带 `paths` 即条件；形态由机制决定，不靠文件里自我声明
- ✗ 把必须常驻的判据塞进 `references/`——模型要用时看不到，等于没写

**C1 显式契约**
- ✓ `asset-guide` 的 `description` 写清触发面（新增／修改／迁移／删除资产前），模型据此决定调不调
- ✗ `description: 帮助处理各种资产`——触发边界模糊，该调的时候想不到

**C2 最小权限**
- ✓ `secrets/` 独立存放且被 `.gitignore` 排除；`protocol_check.py` 只读，阻断与否交给调用方
- ✗ 密钥写进 `SKILL.md` 或台账——落盘即泄漏，「密钥」判据只能事后兜底

**C3 可验证**
- ✓ `hooks/scripts/protocol_check.py` 十一类判据 + 退出码（0 全过／1 有命中／3 阻断区命中），hook 按码行动
- ✗ `skills/last30days/SKILL.md` 涨到 195.3 KB 才被发现——20 KB 上限可机械判，却没有在写入时拦住

**C4 生命周期**
- ✓ 归档空壳写明归档位置、恢复方式与观察截止（60 天）；台账状态词只用「在用／停用／已归档／待核」
- ✗ 废弃 skill 原地留着、不标状态、不写恢复方式——半年后没人敢删

## 边界

- 「只放必要」只对运行时被 agent 读取的产物生效；`notes/`（证据）、`installing/`（台账）、`backups/`、`authorization/`（授权登记）的存在理由是可审计，不是必要。
- 不入表：跨代理可移植（不主动引入跨平台抽象，同一平台优先用原生机制）；「怎么用 AI」类建议。例外必须在对应索引或台账中显式写明理由。
- 引导层（本文件、`CLAUDE.md`、skill）**没有覆盖语义**：两份指令冲突时模型任选其一。要硬约束只能落 `settings.json` 或 hook，因此同一件事禁止存在两份会冲突的副本。

## 加载形态

平台只给四格，每类资产落进其一：

| 形态 | 机制 | 何时进上下文 |
|---|---|---|
| 常驻 | `CLAUDE.md`、无 `paths` 的 `rules` | 每个会话开始 |
| 条件 | 有 `paths` 的 `rules` | 读到匹配文件时 |
| 按需 | skill | 调用，或模型判定相关 |
| 全量 | `@path` 导入 | 会话开始，**不是渐进披露** |

渐进披露靠「L0 放指针 + agent 按需 Read」，不靠平台。
