# Plagiarism Audit

对照一个或多个外部来源，审查文章/代码的抄袭/高仿/洗稿/架构克隆。核心难点不是"找相同词"，而是区分**技术事实描述（允许）**和**原创表达搬运（必改）**。

**法律根基**：判定准则是「接触 + 实质性相似」。接触=抄袭者有机会读到原作（用户提供的来源即默认有接触机会）；实质性相似=两作"神似"，不只看词面。相似判定分两域：**文字表述**（直接复制 / 洗稿改写 / 骨架神似）和 **代码技术**（复制粘贴 / 架构克隆 / 协议违反）。详见下方「抄袭类型分层」。

## 触发

- 用户给文章 + 外部来源（URL/文件/粘贴），要查"是不是抄了"
- 用户说"怀疑直接贴原文""洗稿""高仿""与原文高度相似"
- 用户要求审查"只可参考不可抄袭"是否被遵守
- multi-review-pipeline 检测到用户提供来源时，自动作为第 5 个 reviewer 调用本 skill

## 抄袭类型分层（判定标尺）

评判员判定违规时，按此分层归类。**严重度自高到低**：架构/骨架神似 > 段落洗稿 > 逐字复制。骨架神似排最高——因为换词不换骨，逐句比对容易漏，但实际侵权最重。

### A. 文字表述域

| 类型 | 判定特征 | 严重度 | 改写方向 |
|------|---------|--------|---------|
| A1 逐字复制 | 原封不动或只改极少数词的大段搬运 | 高（低级但铁证） | 整段重写，技术事实可保留措辞重述 |
| A2 洗稿改写 | 同义词替换 / 调句序 / 合并多源产出，逐句可对齐 | 高 | 换切入角度+换自己的举例 |
| A3 骨架神似 | **核心逻辑、叙事结构、分析视角高度相似，即便文字完全不同** | 极高（最难抓、最致命） | 打散原文骨架重排：换切入角度、换章节顺序、换论证路径（如从"四个病根"换成"工程权衡"） |

A3 是审查最大盲区：评判员逐句比容易判"文字不同=安全"，但原文的论证骨架（如"先讲 LLM 无状态→两层架构→四类型→检索三步→设计原则"这个顺序+视角）被整体照搬，法律上同样构成实质性相似。**抓 A3 必须比对：文章的章节顺序、每节的论证路径、独特举例组合、分析视角，与来源是否"换皮不换骨"。**

### B. 代码技术域

| 类型 | 判定特征 | 严重度 | 改写方向 |
|------|---------|--------|---------|
| B1 复制粘贴 | 他人代码完整复制，或只改变量名/注释 | 高 | 重写实现，保留功能换写法 |
| B2 架构克隆 | 无逐字复制，但模块划分/核心算法逻辑/接口设计高度相似（如两语言项目 11 个核心模块完全映射） | 极高 | 重新设计架构，不照搬模块切分 |
| B3 协议违反 | 用了他人开源代码却没遵守 LICENSE（未留版权声明 / GPL 整合进闭源） | 高 | 按 LICENSE 要求补声明或移除 |

B2 尤须警惕：代码"思想"（算法原理、通用思路）不受保护，但"表达"（具体模块切分、独特接口设计、特定实现组合）受保护。判定线=通用思路 vs 独创的架构表达。

## 保护范围（允许 vs 必改的判定线）

司法只保护**独创性表达**，不保护通用思路。判定每处相似前先过这道门：

| 不受保护（允许相似） | 受保护（必改） |
|---------------------|----------------|
| 通用思路、标准算法原理、语言语法 | 原创比喻、金句、独特举例组合 |
| 技术名词、API 名、机制名 | 原创论述框架、原则命名+排列顺序 |
| 官方文档原话、源码常量/函数名 | 给机制贴的原创标签（如"读后即焚""权威的错误"） |
| 固定结构模板（Why/How to apply） | 原创句式封装（"X一致Y可变""两个坑：A和B"） |
| 技术事实（机制本身的客观描述） | 独创的分析视角、叙事结构 |

**未标注来源的引用=重要参考**：合理引用须注明出处+引号。无出处的大段相似，是认定抄袭的关键证据。

## 判定三维度（引用程度看质量>数量）

司法看三方面，评判员须综合而非单看比例：

1. **保护范围**：先判该处是"独创表达"还是"通用思路/技术事实"——前者才进违规判定。
2. **引用程度**：数量+质量并重。**质量优先于数量**——核心逻辑/算法/独创性高的内容雷同，即便比例小也很危险；边缘描述雷同比例大但危害低。评判员须标出"核心区雷同"vs"边缘区雷同"。
3. **是否注明出处**：有规范出处的合理引用可减责；无出处的大段搬运加重。

## 架构：三角色循环

审查不是线性流程，是"计划 → 执行 → 反馈"循环。这次设计直接针对实战漏网：整源漏审（Codex-book 那次）、姐妹段漏改、评判员漂移、单轮 PASS 不可信。

| 角色 | 职责 | 何时跑 |
|------|------|--------|
| **计划生成者** | 读文章 + 来源，产出审查计划；反馈触发时修订计划 | 循环开始 + 调整时 |
| **多审查员** | 按计划派评判员逐源对照，输出残留清单 | 每轮 |
| **反馈者** | 诊断每轮结果（PASS / 漂移 / 漏网 / 卡住），决定继续 / 调整 / 终判 | 每轮结束 |

```
[计划生成者] → audit plan
        ↓
┌─→ [多审查员] 按 plan 派 judges → 收集残留
│        ↓
│   [反馈者] 诊断
│     ├─ 无残留 → [独立终判 judge] 全源复核 → PASS 收工
│     ├─ 有残留 → 改正（姐妹段全改）→ 回多审查员
│     ├─ 漂移/漏网/抓取失败 → 反馈计划生成者 → 修订 plan → 回多审查员
│     └─ 超 3 轮未收敛 → 🔴STOP 人工裁决
└──────────────────────────────────────────────┘
```

## 工作流

### Step 1: 计划生成者 — 产审查计划

读文章 + 所有来源（来源抓取失败按 REFERENCE 多路重试，全失败才能标"无法获取"）。产出 plan 写明：

- **来源清单** × 每来源许可级别（可引用原文 / 仅可参考）
- 每来源**原创元素清单**：比喻 / 金句 / 举例组合 / 论述框架 / 句式封装
- **来源骨架指纹**（抓 A3/B2 用）：来源的章节顺序、每节论证路径、独特视角、模块切分。文章若同顺序+同视角+同路径=骨架神似，判 A3/B2
- **评判员分配**：派几个、每评判员查哪几源（多源拆分，避免单 judge 过载；每源至少 1 个独立 judge；**至少 1 个 judge 专做骨架比对，不只逐句**）
- **终判标准**：什么算 PASS（全源无逐字/洗稿/骨架神似残留；技术事实白名单内不算）
- **技术事实白名单**（初版）：预判哪些是客观机制描述（如 JSONL 追加/清空），写入 plan 供 judge 参考取舍

🔴STOP：展示 plan，等用户确认再执行。

### Step 2: 多审查员循环执行

按 plan 派 `general-purpose` 评判员。每评判员拿：文章路径 + 指定来源的原创元素清单 + 判定标准 + 技术事实白名单（模板见 [REFERENCE.md](REFERENCE.md)）。

输出格式：
```
行号: [文章句] ≈ [来源句] | 判定: 逐字抄袭/高仿/允许 | 理由
```

收集所有评判员残留 → 去重 → 按源 × 严重度排序。

### Step 3: 改正（姐妹段一次性全改）

**姐妹段检查**：同一例子/论点常分散多处（正文 + 代码块 + 表格 + 检索示例）。改前按主题 grep 全部位置，一次全改。改写策略：换切入角度 → 换自己的举例（目标读者场景）→ 换叙述顺序 → 技术事实保留措辞重写。

### Step 4: 反馈者 — 诊断 + 决策

每轮结束反馈者判定：

| 诊断 | 动作 |
|------|------|
| 无残留 | 派**独立终判 judge**（未参与前轮）全源复核 → 确认则 PASS 收工 |
| 有残留 | 改正后回 Step 2 |
| 评判员漂移（同技术事实反复判） | 人工兜底：客观机制→保留+白名单登记；措辞搬运→改。反馈计划生成者把该元素加入白名单 |
| 新类型漏网（整源漏审 / 姐妹段 / 抓取失败） | 反馈计划生成者：补抓取路径 / 补 grep 主题 / 补评判员覆盖 |
| 超 3 轮未收敛 | 🔴STOP 人工裁决，不自动放行 |

**终判 judge 必须独立**（没参与过前轮），全源复核 PASS 才算真结束——防"改的人自己评"乐观偏差。

### Step 5（条件）: 计划调整

反馈者触发时，计划生成者修订 plan（增减来源 / 换抓取策略 / 调评判员分配 / 扩技术事实白名单 / 补姐妹段 grep 主题），再回 Step 2。

**Loop guard**：上限 3 轮调整，仍不收敛 → 🔴STOP 人工裁决。

## 来源边界

- **可引用原文**：目标项目自有文档、官方文档/源码、技术规范
- **仅可参考**：第三方文章、博客、教程、他仓文档——严禁逐字/高仿/同义改写搬运

未标注时主动问用户。默认第三方一律按"仅可参考"。

## 不要做什么（反例）

| # | 反模式 | 正确做法 |
|---|--------|---------|
| 1 | 单次抓取失败标"无法获取"跳过来源 | 多路重试（raw/编码/gh api/搜索），全失败才报；漏审整源是最大风险 |
| 2 | 改一处忘改同主题姐妹段 | 改前 grep 全部位置一次全改 |
| 3 | 单轮评判员 PASS 就收工 | 独立终判 judge 全源复核；评判员会漂移 |
| 4 | 把技术事实描述当抄袭改 | 白名单登记客观机制；只改措辞搬运 |
| 5 | 只查逐字相同 | 同义改写、句式重合、原创比喻/金句借用都算 |
| 6 | 不区分来源许可级别 | 官方/自有可引用，第三方仅参考，未标注先问 |
| 7 | 改的人和终判的人同一个 agent | 终判 judge 必须独立，未参与前轮 |
| 8 | 无 plan 直接派评判员 | 先出 plan + 🔴STOP 确认，防止整源漏审 / 分配不均 |
| 9 | 逐句 PASS 就放行，漏了骨架照搬 | A3 骨架神似：文字全不同但章节顺序+论证路径+视角雷同=仍侵权。至少 1 个 judge 做骨架比对，比"换皮不换骨" |
| 10 | 代码只查词面，漏架构克隆 | B2：模块切分/接口设计/核心逻辑映射高度相似=架构克隆，即便无逐字复制 |
| 11 | 用比例当唯一标尺 | 质量>数量：核心逻辑/算法雷同即便比例小也危险，须标"核心区"vs"边缘区" |
