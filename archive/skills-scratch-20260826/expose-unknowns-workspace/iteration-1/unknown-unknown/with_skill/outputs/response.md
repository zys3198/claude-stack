## 1. 判级：未知的未知（最高级）

“做一个智能客服”只是产品标签，不是可执行需求。当前至少缺少：

- 服务谁：访客、客户、会员，还是内部客服
- 解决什么：回答问题、推荐、查询订单、办理业务，还是转人工
- 服务边界：哪些问题能答，哪些必须拒答或转人工
- 数据依据：知识库、工单、订单系统、人工话术是否存在
- 行动权限：只读，还是允许下单、退款、改地址等
- 成功标准：准确率、转人工率、响应时间、降本，还是获客
- 风险约束：隐私、财务、医疗、法律承诺、投诉留痕
- 交付形态：演示原型、内部试用，还是直接上线生产

此时直接选模型、搭知识库或写聊天界面，等于让 AI 替甲方填空，风险最高。

## 2. 按级出牌

### 第一张牌：先扫盲，不做方案

先让甲方理解“智能客服”至少有四种完全不同的东西：

1. **FAQ 问答**：根据资料回答“营业时间、产品参数”
2. **流程引导**：询问信息后判断“该走哪个售后流程”
3. **业务办理**：查询订单、改地址、退款、预约
4. **智能分诊**：识别问题并转给合适的人工团队

风险和成本从 1 到 4 逐级上升。第一轮只要求甲方选：

> 我们第一期更接近：  
> A. 自动回答常见问题  
> B. 辅助用户完成一个流程  
> C. 直接操作业务系统  
> D. 自动分流给人工  
> E. 还无法判断

如果选 E，不进入技术方案，继续采访。

### 第二张牌：用选择题采访，不问“你想要什么”

把下面的问题按顺序问，要求每题给出具体例子：

1. **谁会使用？**  
   新客户 / 已购买客户 / 会员 / 内部客服

2. **最近一个月最常见的前三类咨询是什么？**  
   不接受“什么都可能”，要工单、聊天记录或人工回忆的具体例子。

3. **客服最终要完成什么结果？**  
   给答案 / 推荐方案 / 收集信息 / 查询状态 / 修改数据 / 转人工

4. **机器人答错时，哪类错误最不能接受？**  
   答非所问 / 编造政策 / 泄露隐私 / 错误退款或承诺 / 延误人工处理

5. **哪些事情绝对不能让机器人做？**  
   例如退款、价格承诺、合同解释、删除用户数据等。

6. **答案的唯一依据是什么？**  
   现有 FAQ / 产品文档 / 工单系统 / 订单系统 / 人工经验 / 尚未整理

7. **什么时候必须转人工？**  
   用户情绪、置信度不足、涉及金额、投诉、身份核验失败，还是其他条件。

8. **第一期在哪个渠道使用？**  
   官网 / 小程序 / 企业微信 / App / 电话 / 内部工作台

9. **上线后用什么判断成功？**  
   自动解决率 / 转人工率 / 首次响应时间 / 客服工时 / 转化率 / 客诉率

每个答不出来的地方明确标记为“未决策”，不要替他们默认。

### 第三张牌：要样例，不要继续要抽象描述

让甲方提供以下材料，脱敏即可：

- 20～50 条真实客服对话或工单
- 当前 FAQ、产品说明、售后政策
- 人工客服标准话术和转人工规则
- 3 条“答错会造成严重后果”的案例
- 涉及的系统和接口清单
- 他们认为“理想回答”是什么样子

没有真实样例，就只能做**概念演示**，不能承诺生产可用。

### 第四张牌：把待决策项置顶

后续计划必须先列这些业务决策，再列模型、接口和页面等机械工作：

1. 第一用户群和第一场景
2. 机器人能回答什么、不能回答什么
3. 是否允许执行真实业务操作
4. 知识和业务数据的权威来源
5. 转人工条件
6. 成功指标和验收样例
7. 隐私、合规和留痕要求

## 3. 当前建议

最强的“先做 Demo”理由是：客户往往看了具体对话和界面，才知道自己真正想要什么。最强的反对理由是：Demo 很容易把客户锚定在错误场景上，最后变成“看起来会聊天、实际上不能上线”。

**暂定判断：先做一个可丢弃的窄场景原型，但前提是甲方先选出一个场景并提供真实样例；不要直接承诺完整智能客服或生产上线。**

你可以直接把这段发给甲方：

> “智能客服”可以是知识问答、流程引导、业务办理或转人工分诊，范围和风险差异很大。我们先不讨论模型，贵方请先选定第一期服务对象、前三类真实问题、机器人允许和禁止做的事、必须转人工的情况，并提供一批脱敏对话和现有话术。若这些信息暂时无法确定，我们先按一个具体场景做探索性原型，不把它作为完整生产系统承诺。

**两分钟下一步：**把上面的甲方话术发出去；在拿到“一个场景 + 真实对话样例 + 权限边界”之前，不开始正式开发。
