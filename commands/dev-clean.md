按顺序执行，每步都把结果给用户看。

**第一步** 运行状态脚本：

```
C:/Users/zys31/AppData/Local/Programs/Python/Python312/python.exe "C:/Users/zys31/.claude/hooks/scripts/session-status.py" $ARGUMENTS
```

**第二步** 把 `[可清理]` 和 `[游离]` 两组整理成清单。`[孤儿目录]` 只报告，不处理。

`[可清理]` 指位于仓库 `.claude/worktrees/` 下的空工作树，用 `git worktree remove` 删除。
`[游离]` 指建在别处的目录，删除前先确认用途。

**孤儿目录一律不删。** 它们在磁盘上有完整工作副本，但 git 已经不再注册，里面的改动不在任何分支上。清单里标了有没有同名分支：标「无同名分支，内容只在此目录」的那些，目录是内容的唯一副本，删掉就找不回来了。这类目录由用户自己判断怎么处理，本命令不执行删除。

**第三步** 列出准备删除的完整路径清单，等用户明确同意。删除不可恢复，未获同意不得执行。

**第四步** 用户同意后逐项执行：

```
git -C <仓库路径> worktree remove <工作树路径>
```

只删工作目录，不删分支。分支会留在 `git branch` 里，随时可以重新检出。

有未提交改动的工作树会被 `git worktree remove` 拒绝，这是设计如此。被拒绝时不要改用 `--force`，先把改动归位到分支上再删。

**第五步** 汇报删了几项、失败几项、失败原因。失败项保留原样。
